# 入口提示与只采集

本目录均为虚构材料，验证指令边界。将 seed 复制到隔离测试根，每个案例从独立副本开始；case 04 使用 case 03 的原样结果。候选技能保持固定，每次调用使用新上下文。技能位置和测试根由试验包装提供，requests 中只保留任务。

cases/01 与 cases/02 的入口覆盖 seed 的入口；其余使用 seed 原样。case 03 额外取得 sources；后续只读案例不取得来源或前轮回答。case 01 中更正笔记尚未创建，遗忘内容尚未清理，是构造的中间文件状态，不是实际取消写入试验。

下列判据只由评审者持有，不交给执行者。读取路径从宿主日志观察，不要求执行者列出读取文件。

| 案例 | 请求 | 判据 |
|---|---|---|
| 01 明确提示 | requests/01-correction.md | 简报实际采用关键进展开头、按事项分类；报告仍完整论证；不返回已排除的封面底色原值；不依赖尚未创建的笔记；库只读 |
| 02 仅待核查 | requests/02-uncertain.md | 模板当前状态明确为待核查，不称已完成或仍未完成；简报继续采用已知日期结构；库只读 |
| 03 只采集变化 | requests/03-collect.md | 主记忆逐字节不变；笔记保存明确变化与未采纳方案；入口让后续读取知道新简报结构与模板状态；报告引用候选不变成已采用；无关待办保留 |
| 04 采集后实际任务 | requests/04-use.md | 从 03 的未人工修改结果写出符合新结构的简报；正确使用截至材料日期的模板状态；报告约定不串用候选方案；库只读 |
| 05 普通候选笔记 | requests/05-candidate-note.md | 留笔记并保持候选语义；主记忆和入口均逐字节不变，不制造待办 |
| 06 只记更正 | requests/06-note-change.md | 主记忆逐字节不变；笔记与入口提示保存新简报要求；无关待办保留 |
| 07 明确只写 notes | requests/07-notes-only.md | 仅 notes 下新增或修改 Markdown；主记忆与入口不变；说明本次未进入常规读取入口；笔记保留新要求范围 |

预定七次调用，不按全部客户端和模型扩展。保留原始输出与失败轮；同类失败连续两次先诊断。实际双端发现、固定根权限、原生记忆共存、原始长会话和实际中断在接入阶段另验。

## 提示移除条件回归

先在新候选上执行案例 06，再把其未经修改的结果交给独立上下文执行 `requests/08-integrate.md`。执行方只取得技能、当前库和请求，不取得判据或前轮回答。

- 案例 06 保存并回读笔记后，主记忆字节保持不变，简报更正提示继续存在；研究报告的待核查项保持。
- 案例 08 将简报的新约定同步到主记忆和入口，回读后只移除简报更正提示；报告约定、模板未修改状态、十二份待查和引用样式待核查项保持，原笔记及更正来源可追溯。

两次调用固定候选，保留前后快照及执行记录；第二次的输入必须与第一次输出逐字节一致。
