# 1.8.0 小规模技能试用

本目录是虚构来源材料。项目之外新建隔离目录，复制本目录的 sources/ 和候选包的完整 skills/，指定测试 home 下的 `.agents/memory/`。不读取真实记忆或客户端数据。

本轮使用 GPT-6.1-sol、high，子代理不继承主线程历史，明确加载指定 Skill。禁止 Python、status 与专用读取器，使用宿主文本工具实际读写。输入材料与技能是执行上下文，下面的核对判据由主线程持有，不注入执行代理。

## 任务与核对

1. update 整理 sources 的 01—03 三份材料，04 留给后续更正回归。核对全局语言、简报与报告范围、未采纳建议、三份已查/十二份未查、模板尚未改；同源转述合并，普通问答无产出。
2. 同一写入代理收到 note 更正：“工作简报改成开头先列关键进展，正文按事项分类。只改简报，研究报告仍保留完整论证和必要依据。模板还没有修改。”随后重新整理同一批旧材料。核对更正保持、旧材料不覆盖、不重复产稿、其他范围不变。
3. 新的只读代理只拿到 Skill 与结果库，询问两类文稿写法、模板是否修改、文档核查剩余，并要求本次英文回答。不得拿到源材料或前轮答案。核对答案与实际读取路径；前后文件 hash 应相同。
4. 复制结果库，在入口追加一个尚未同步主记忆的明确更正：“研究报告只保留结论、适用条件和必要依据，推导按要求展开；只影响报告。”另一个独立只读代理询问报告要求及简报是否跟随变化。这是模拟中断后的文件状态，不是实际杀进程测试。

## 本轮观察

形成、范围、更正保持与两次独立查询的答案符合材料。正常读取首轮展开 5 个记忆文件，包括全部三篇笔记；收紧 recall 的停止条件后，用全新上下文复测仍读取 3 个记忆文件，其中一篇更正笔记并非回答所必需。保留首轮不足，读取成本判为部分通过。

共 4 个独立子代理、5 次执行回合：形成 1、同代理更正加旧材料复读 1、正常查阅 1、模拟中断查阅 1、修订后的正常查阅复测 1。读取路径取自代理返回清单，来源与结果库的只读性由主线程前后 hash 核对。

本轮未验证真实客户端自然触发、私有格式接入、长期规模、并发、遗忘后重采集或 Codex 原生同题基线。程序测试和行为观察分别见 [验证记录](../../docs/validation.md)。

## 整合取舍回归

复用首轮形成后的隔离库，向入口添加一项仍需核查的研究报告事项，再让独立进程按自然请求整理 sources 的 01—04。执行方只取得技能、初始库和材料；核对以下语义，不按固定措辞评分：

- 简报的当前要求被替换，主记忆和入口不再把两种组织方式并列作为有效要求。
- 研究报告、默认交流语言、日期方法及具体未完成事项保留；研究报告的待核查项不被清除或阻碍简报更正保存。
- 笔记能解释改变，主记忆保留可直接采用的要求；普通问答及同源转述不单独产稿。
- 本轮处理数量、合并回执不进入长期入口；来源不改写，只写指定测试根。

真实材料回归另复用上一批 V1 形成后的快照与相同 V2 输入，保持模型、提示和查阅问题不变，检查更正收敛、入口取舍、历史细节位置和后续回答。私有输入、命令与实际结果保存在 local/，不收入本目录。

## 来源归属与连续维护回归

[来源归属小例子](attribution/README.md)区分用户明确默认、助手当次行为和原生摘要作者的推广。初始库、来源和语义判据分开，不用字面关键词替代范围判断；新摘要的省略也不自动撤销旧知识。

在固定候选上顺序验证完整维护过程，各阶段使用新的模型上下文：先按 01—03 形成初始库，保留一项研究报告引用样式待核查；通过 note 更正简报，重新整理同一批旧材料；再明确要求删除交流语言偏好并禁止旧材料恢复，同时保留其他知识；再次重读原来源，随后在没有输入变化的条件下重复更新。核对更正与遗忘都不复活、其他待办不被清空、最后一次无变化更新不产生重复产物。

最后使用新的只读上下文询问两类文稿、模板状态、未核查范围及库内是否还保留语言偏好，并明确要求英文回答。另用无历史依赖的算术问题检查是否跳过记忆读取。保存每阶段原始产物、实际读写命令及源文件和结果库的前后比较；不人工修补生成内容后改判。
