# Codex 与 ZCode 来源适配验证

本场景用虚构内容验证来源继承、跨端归并、日期及更正，不读真实客户端，也不替代真实来源抽样。目录名不是发布版本；源码改动后的实际模型结果记录到仓库验证报告。

运行 `python3 -B evals/source-adaptation/make_fixture.py <新的实验目录>`，再把待测八个 XMemory Skill 和 Codex/ZCode reader 放入该实验目录。生成器拒绝覆盖已有目录。评分说明不提供给执行者；模型只收到 Skill、来源、已配置的空库和下面的任务。

> 按 XMemory Skill 为 Maple 建立记忆。使用配置中选择的全部已有记忆，以及北京时间 2026-10-08 至 2026-10-09 的会话；整理必要的记录、日期视图、项目知识和接续入口。来源只读，仅在指定 memory 目录写入。完成后说明当前状态和未完成范围。

## 核查实际文件与行为

1. Codex V1/V2 同一 thread 的来源可分别定位，原会话与摘要没有变成多次独立执行或重复日块。摘要旧路径失效时能在选定归档目录找到原件。
2. 当前格式为 JSON Lines；实际工具结果仅证明三个小样本通过，完整批次失败、未部署。保存时间较新的错误摘要及过期 ZCode 索引没有覆盖原件。
3. Codex 汇总中独有的 `E_CURSOR_STALE` 处理方法、命令及“仅限增量导出”的条件仍可找回；会话时间范围没有误排除已选记忆中的更早经验。
4. ZCode 的通用 `project-<hash>` 目录通过正文及数据库 directory 归到 Maple；主题保留 origin 与后来更正的不同会话来源，未仅凭 origin 升格为完整单会话提炼。
5. 更正只适用于 Maple 导出说明；`type: user` 未导致全局泛化，“本次演示只给命令”未替代长期约定。
6. 事件按 10 月 8、9 日归属；导入文件更新时间没有变成事件日。无日期主题保留缺口并按采集日归档，没有借 origin、相邻文件或 mtime 编日期。
7. 保存输入前后哈希、实际命令、输出库及模型回答。检查真实字段、出处和可读链接，不能只根据完成声明判定通过。

另开只读新会话，仅提供生成的库及 recall Skill，询问格式选择、验证进度、游标错误处理、说明顺序和适用范围，核对来源与答案并确认库未修改。按实际遗漏修订，记录失败结果；不由主线程改好产物后宣称独立执行通过。

## 原生记忆与 XMemory 共同使用

上面的隔离实验只验证 XMemory 自身。使用 `python3 -B evals/source-adaptation/make_coexistence_fixture.py <新的实验目录> --skills plugins/xmemory/skills` 生成可控的虚构原生记忆与测试宿主。`recall/prompt.md` 提供六个只读环境，`remember/prompt.md` 提供一次写入请求；分别由无前轮上下文的执行者完成，不提供本页判据。保留两套测试记忆入口；执行器可以关闭真实宿主记忆以避免污染，但不得移除夹具中的原生协议和内容，也不能将结果称为真实客户端自动注入验收。

| 场景 | 应观察到的行为 |
|---|---|
| 原生记忆保存 Maple 的说明顺序，XMemory 保存其他客户端的导出决定 | 回答同时采用两边的相关信息；原生内容无需先导入，XMemory 命中后仍使用相关原生内容 |
| 一边有明确限定范围的用户更正，另一边保存时间较新但仍转述旧结论；交换两边的内容重复验证 | 两种方向均按更正及证据判断，不固定偏向原生记忆、XMemory 或文件时间；同源副本不重复计证 |
| XMemory 未启用原生记忆来源，或某一套库不可用 | 前者仍按宿主协议使用原生记忆，后者按已有依据回答并保留缺口；不为查阅强制导入、开关功能或扩大扫描 |
| 被排除的 Codex 会话仍留在原生摘要，另一个 ZCode 会话具有相同 ID 尾部 | 查阅实际读取排除配置，不复述或采用被排除内容；按完整客户端身份保留 ZCode 的独立依据，同源转述不重复计证 |
| 用户要求记住一个长期项目约定，测试宿主提供受支持的原生写入机制 | 两套机制按各自规则处理；XMemory 写入不替代原生维护，保留原生入口和原有规则，不直接覆盖原生生成文件或复制整套库 |

查阅前后核对全部输入的内容与 mtime；写入场景核对原生入口、Skill 和配置未被改写，读回两套库的实际新增内容及项目范围。语义结果需人工核对，不能只用关键词匹配替代；实际执行结果见 [验证报告](../../docs/validation.md)。
