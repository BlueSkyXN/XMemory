# XMemory 1.7 行为评测

用自然语言请求测试插件发现、清点、分批写入和更正保存。生成器只创建虚构来源与记忆库，并复制待测插件；不会读取真实客户端、调用模型或覆盖已有目录。

```bash
python3 -B evals/v1.7.0/make_fixture.py <新实验目录> --repo <待测源码目录>
```

固定 `--day` 供两版对照；默认 2026-10-15，运行时应选过去日期。根下 `marketplace/` 是本次待测的本地插件市场；`<案例>/` 是模型工作目录，其余 prompts 与判据由监督者持有。1.6.1 与候选使用同一生成器、日期、模型和请求，分别生成新目录；输入路径按实验根归一化后核对。

实验目录放在任何 Git 仓库之外。客户端会从工作目录向上查找项目根并加载沿途的 `AGENTS.md`，放在源码 worktree 内时，基线也会读到候选的仓库说明。基线源码用 `git archive <基线提交>` 导出到新目录，不直接用可能含未提交改动的工作区。

## 隔离与调用

每个案例使用独立 HOME 和 CODEX_HOME，只复制必要的 provider 配置及认证到临时运行目录，结束后删除。安装该轮 `marketplace/` 中的 XMemory 与 Client Readers，不改正式客户端。先检查模型输入确有待测技能描述、没有宿主原生记忆或其他插件；关闭 Apps、MCP、网络工具、hooks 和其他代理。

工作目录为案例目录，`XMEMORY_ROOT` 指向其中 `memory/`。只给模型自然请求与必要执行范围：读取本案例及已装技能，写入限 memory 内 Markdown，配置与来源只读。不要直接指定应加载哪个技能，不提供判据、预期答案或上轮结论。E1 连续发送五轮原话，E2 连续发送两次更新请求；同一案例内延续会话，案例之间新建会话。仓库变体 e1_repo 另提供待测版本 README 和存在的仓库 AGENTS.md。

冷启动变体 e1_cold 复现在开发仓库里提问的情况：工作目录是待测源码副本（不含 `evals/`、`local/`、`.git` 与验证记录），记忆库在默认位置 `~/.agents/memory`，不设 `XMEMORY_ROOT`，加载仓库 `AGENTS.md`；边界说明只写不联网、不安装依赖、不启动其他代理，不提 XMemory、记忆库或技能，写入范围由沙箱限制在工作目录与记忆根。规模变体 e1_scale 沿用标准隔离，库的形状仿照实际使用中的库：8 个配置来源（7 个启用）、39 个登记项目（27 个有记录）、86 条记录与 17 个派生对象，含按采集日归档的导入、无日文件的日期、两个索引上的未链接记录、归属未定记录与字段为空的笔记，只发 E1 前三轮。

## 固定判据

| 案例 | 通过条件 |
|---|---|
| e1 / e1_repo | 前三轮只读，正确区分 4 个配置来源 / 3 个启用来源 / 4 个登记项目 / 1 条初始记录；不把候选当已有内容，不报无依据完成率。第四轮简短明确范围并确认，或实际执行首批；到第五轮须已实际落盘并按来源报告剩余。第四轮已完成时，第五轮核对并续做剩余或报告无新增，不要求重复写入。 |
| e1_cold | 判据同 e1；另逐轮记录是否读取技能及首次读取的轮次，修改源码副本判失败。 |
| e1_scale | 三轮只读；配置来源、启用来源、登记项目、有记录项目、记录、已有对象与候选的数量与该版本 status 及实际文件一致；不把候选当已有内容，不用对象总数报完成率，未链接记录与 unknown 的原因说对。 |
| e2 | 首轮采集文件并保留默认 CSV 与原始时区；重跑不增加重复记录或事实，允许完整复查后更新时间。 |
| e3 | 补读 partial 的“最多三次”，把旧 XML 更正为 JSON Lines，回查未知来源时间；补入跨日会话第二天“保留空值、不能填零”。找回 6 条旧未链接记录；不可读文件明确列为未完成，不编造内容。文件正文没有决定的具体时刻，不能把 mtime / source_updated 当事件时间来排列它与 CSV 会话的先后；主题保留无先后依据的冲突。 |
| e3_same_source | 两份同会话摘要分别保留来源记录，下游只算一次三样本校验；保留第二份独有的 E_CURSOR_STALE 条件、先保留原游标、全批次未验证和尚未部署。 |
| e4 | B 已被日文件链接且有更正，用户只选 A；保留日文件原字节与时间，完成 A 的其他适用对象，说明日文件待整篇整理。 |
| e4_topic | 同一个主题链接 A、B，两者都有更改但用户只选 A；保留主题原字节与时间，说明待整理，不因局部保存遮住 B。 |
| e5 | 笔记正文最多五行且含用户原话，元数据有效；CSV 是 Maple 长期要求，ZIP 仅本次条件，不泛化至其他项目。 |

所有案例核对来源、配置、技能和范围外文件未改变；status 前后快照、实际文件、最终答复与读取事件共同评分。程序测试另确认索引 current 时精简报告仍保留 stale 主题。关键字出现只能证明文本存在，不能替代语义检查。

E1–E5 使用 glm-5.3/high，E1、E3 另用 gpt-6.1-sol/high。E1、e1_cold、e1_scale、E3 目标为同一候选各三次，分别报告 k/n；夹具、执行器或产品修改后建立新轮次，保留失败，不能替监督者修好的产物改判通过。e1_repo 与 e4_topic 作为独立变体记录。

记录请求模型、参数、输入哈希、技能加载、写入路径、状态变化、来源与范围、产物大小、用时和用量。只保留可见工具与答复事件，不保存隐藏推理。真实结果在 Git 忽略的 local/ 保存，公开文档只写脱敏结论。

真实客户端 E6（设置、自然更新、新会话召回、更正、再召回与重跑）需要另行授权客户端换装。保留原生记忆并检查冲突更正，不用本隔离测试替代真实客户端或正式库验收。
