## 独立查阅任务

另建一份旧库，加入写入阶段产生的新记录，但保留旧画像和旧主题。再只修改一个无关画像条目，并刷新上层文件的保存时间，使它们晚于更正记录；不能更改更正记录的正文或伪称已处理它。

给另一名全新代理正式技能和这份库，禁止读评分说明、写入阶段对话和其他测试输出，要求只读回答：

1. 对部署说明，用户希望以后采用什么顺序？适用于哪些任务？
2. Maple 最终选了什么导出格式，为什么？
3. 本次演示的要求是否应作为以后所有任务的默认规则？

三个回答分别应采用新的长期顺序及范围、已采纳的 JSON Lines 与理由、仅本次演示有效。必须引用新记录，指出相关旧对象未同步；不能只引用旧对象，也不能因其 updated 较新跳过记录。检查回答前后的库快照，确认查阅没有写入。

## 程序回归与边界

- 新记录晚于画像/项目入口、早于全局摘要时，摘要报告 `upstream_newer_sources` 及 `upstream_updates`；上游和摘要依次处理后可以恢复 current。
- 普通记录的 `external_source_not_checked` 不使摘要永久复查；无依据而未创建的画像不强制成为待办。
- current 与 updated 都不表示语义上吸收了所有记录；局部更新后遗漏相关更正的风险由独立查阅任务覆盖。
- 保存宿主、模型、请求、实际答案、读取文件列表、文件变化与评分结果。代码回归不替代代理行为测试；单轮合成验证不代表真实客户端自然触发率、长历史质量或成本。

## 普通接续的同输入比较

固定一份经用户允许的候选库，复制为两个内容、mtime 相同的只读输入；保留修改前后的技能快照。对两组使用相同模型、推理强度、隔离设置和普通接续问题，例如“接着上次做这个项目，目前已确认哪些进展，下一步先处理什么？”不额外要求输出完整审计报告，也不设置读取文件数上限。

分别保存实际答案、工具调用、展开内容量、用量、耗时和输入只读检查。先比较事实、条件、未知项与来源是否正确，再看阅读和回答成本。单轮差异不能外推为稳定提速比例；库内容发生变化后，不能把差异全部归因于召回技能。

## 更正后仍能深入核查

沿用前述 Maple 场景，给新代理加入一个带原件定位的合成构建记录：可读日志只证明三个小样本测试通过，大文件测试段截断，记录标为 partial。将用户更正原话保存为可读取的合成源文件，不向作答代理提供评分说明。

要求代理回答当前格式、部署说明和本次演示的区别，给出更正原话，并核实构建记录证明了什么。验收应确认：即使旧入口保存时间更晚，仍采用新更正；确实回读指向的原件；小样本通过不扩写成大文件或完整验收通过；查阅未写入。

## 内容取舍与入口收尾

在原库副本上整理指定项目的主题、索引、意识、一个选定日总结与全局摘要，记录和范围外对象保持原样。逐项核对：

- 主题突出做法、适用条件与例外；历史数量和验证过程可从记录回查，关键命令、版本和错误原词仍可定位。
- 来源的 partial、二手证据、截至日期和未决事项保留；整理者的本轮操作说明不反复进入各个主题。被记录任务本身的实验条件仍可保留。
- 意识与入口吸收本轮已完成的内容，保留其他有效入口，不用新保存时间冒充未知的来源覆盖。
- 内容缩短不单独算通过；应检查事实、决定变化、适用范围、例外、未决事项及链接是否丢失。
