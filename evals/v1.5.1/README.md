# XMemory 1.5.1 最小效用验证

这里的 Cedar 项目、会话和结果全部是合成材料。它们用于检查代理能否从记忆恢复事实、条件、时间与出处；没有真实个人信息，也不代表已经完成真实客户端验收。

## 材料与标准答案

- `inputs/`：两份原始会话、一份二手摘要和一个项目文件。二手摘要与原会话描述同一事件，不能算两份独立支持。
- [cases.json](cases.json)：六个问题、必需事实、禁止推断、可逐字定位的证据与遗忘后的判据。评分者读取，作答者不读。
- 后续 [1.5.2 增量更正场景](../v1.5.2/README.md)：额外验证即时同步，以及入口未更新或局部保存时间较新时的独立只读查阅。它与原六题分别记录结果。

## 执行方法

1. 在临时目录新建记忆库，时区 UTC，项目名 `cedar`，只选择此处四份输入。把原始会话视为合成原件，其他两份分别视为外来记忆和项目文件；不访问真实客户端或改其配置。输入中的 `native_id` 是明确提供的原生 ID，`reader_ref` 仅用于定位。
2. 使用本版本技能制作记录，并按问题需要更新日总结、项目总结、意识、画像与入口。按会话的一天拆记录；二手文件只写一份，用实际事件日关联，source_updated 取材料给出的来源更新时间，updated 取本次系统时间。没有画像依据就保持 USER.md 不存在。
3. 在不继承建库对话的新会话中，只提供技能、生成的库和 `cases.json` 的问题文本，先回答前五题。允许沿记录回溯合成原件，不提供标准答案。保存实际回答与所读文件列表到测试输出目录，不能保存到记忆库充当来源。
4. 在该临时库执行第六题的明确遗忘请求，再开新会话复查。再次按相同四份输入采集，确认被排除部分不会回流；二手文件中的对应转述也应排除，另一客户端同 ID 的会话保留。
5. 评分者逐题核对：必需事实齐全、没有禁止推断、引用可回溯到对应证据，三项都满足才算该题通过。第六题还须读回库和排除列表；仅全文搜索无命中不能替代支持关系检查。

## 验证边界

1.5.1 发布时已核对六题的证据引文能定位到输入文件。程序的跨日、更新时间、身份兼容与只读性质由 `tests/test_xmemory_status.py` 验证。这些结果不是独立模型得分；当时上述新会话建库、问答和遗忘后再采集尚未执行。增量更正场景的后续结果单独登记在 [验证报告](../../docs/validation.md)，不把它当作原六题或真实客户端验收的通过率。

实际执行时记录：版本或 commit、宿主与模型、输入范围、问题、实际答案、证据引用、每题结果与错误原因。临时输出可放在忽略的 `local/`，不用新增产品运行状态。
