# 更正与撤回

先确认本次要求及范围。报告错误不自动授权批量删除；明确的“更正这条、忘记这件事”允许处理对应的 XMemory 内容，不包括原生客户端、备份和外部系统。正文更正和撤回由手动整理执行；定时整理只把建议写进意识的“记忆候选”，以及标记下文所述已声明的替代关系。

## 更正

按主题名、要点或来源查到旧主题，读取完整条件，检查引用它的主记忆要点、意识和其他主题。保留适用范围，更新当前结论，必要时记录替代关系和更正时间。

记录技能在对话中收到纠正时，只新建一个主题草稿，并在 `supersedes` 写旧主题名。整理先核对：目标存在、范围相同、各自适用条件清楚、新主题已经生效、没有竞争或互相替代的冲突。满足时：

- 定时整理只把旧主题标为“已替代”，更新主记忆要点，不合并两份正文；
- 手动整理可以在授权范围内合并必要内容。

不满足时不强行替代：保留旧主题，在意识“冲突与未知”登记双方依据和来源地址。调取在整理前也核对这些条件：关系明确且已生效时采用新主题；未来才生效的，当前继续用旧主题并说明切换时间；有冲突时说明双方依据，不按文件新旧选择。调取全程只读。

足迹建立后不修改。足迹内容有误时，新建一份更正足迹并指向原文件。

用户偏好变化时，用 `valid_from` 说明从何时起采用新偏好，不说过去从未有过旧偏好。客观状态变化要有对应结果，不能用偏好修改代替事实验证。

## 忘记

1. 定位要撤回的内容，以及本库内的派生内容：相关足迹、每日记忆、意识、主记忆要点和主题。只处理明确范围。
2. 清除活动正文和派生内容中的被撤回信息；需要保留文件身份时，用不含原文的简短撤回标记。整份文件只包含该内容、且用户明确要求删除时，可以删除该文件并修正链接；删除前读取确认没有混入其他内容。撤回是唯一允许修改已有足迹的情况。
3. 在 `state/withdrawn.md` 记录条目 ID、可安全保留的来源地址、撤回日期、执行者和不泄露内容的原因，不复述敏感内容。如果地址本身会泄露该信息，改用不含敏感含义的本地 ID，并说明匹配能力降低。
4. 后续采集或记录遇到相同 ID 或来源，不自动重新收录。用户明确要求恢复时，按新请求处理并记录恢复关系；身份不明的相似内容，不能声称已经可靠拦截。
5. 回报实际清除范围和未覆盖部分。不要新建包含被遗忘原文的备份；意识副本中含有被撤回内容的，一并清除。

用户要求连撤回标识也完全删除时，按其明确范围处理，并说明以后无法依靠该标识阻止旧来源被再次采集。

## 边界

纯文件约定不提供物理擦除、备份清理、云同步删除或原客户端删除。原始资料可能仍存在，不能承诺“所有地方都已忘记”。记忆库若用 Git 同步，历史提交里仍有原文，彻底清除需要另行处理历史并说明影响。处理派生内容时按主题和来源定向搜索本库，避免漏掉正文引用。
