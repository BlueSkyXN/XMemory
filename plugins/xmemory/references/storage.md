# 文件格式

这是给 Agent 和人共同阅读的文件约定，不是客户端内部数据库 schema。模板中的占位字段都要替换为实际内容，不适用的可选部分删除；未知事实写未知。头部统一用 YAML front matter，字段名在含义相同处对齐 OMPI 工作草案，但不宣称与其兼容。

## 目录

```text
~/.agents/memory/
├── config.toml                  配置
├── MEMORY.md                    入口：常驻条目和索引
├── notes/<topic>.md             记忆：一主题一文件
├── CURRENT.md                   近况：只由整理重写
├── BACKLOG.md                   积压：需要时才建
├── WITHDRAWN.md                 撤回墓碑：需要时才建
├── records/YYYY-MM/
│   ├── YYYY-MM-DD.md            当日文件：每次整理追加一节
│   └── <event>.md               事件文件：只新建，命名见下文
└── projects/<id>/               各项目同样结构
```

这是用户主目录中的唯一默认记忆库，不是工作区内的 `.agents/memory/`。同一台机器上的客户端共用该用户的记忆根。多台机器使用同一逻辑记忆库，各机器默认位置为 `~/.agents/memory/`，通过用户选择的同步方式保持内容一致。`projects/<id>/` 是库内分区，范围由所在目录决定：库根为 `personal`，项目目录为 `project:<id>`。

初始化只创建配置、根入口和明确登记的自管项目入口。没有数据不创建空目录或整套模板。所有详情仅存一处；跨项目查询按配置选择相关项目，不另存一份全局按日副本。

## ID 与文件名

- ID 使用小写字母、数字和连字符；记忆的 `identifier` 等于文件名主干，建立后保持稳定。
- 记忆文件：`notes/<topic>.md`。同主题已有文件时，记录新建 `notes/<topic>-<4位随机串>.md`，由整理合并。
- 事件文件：`records/YYYY-MM/YYYY-MM-DDTHHMM-<短名>-<4位随机串>.md`。日期时间是记录时间，短名描述内容，随机串由小写字母和数字组成，防止多台机器在同一分钟生成同名文件。
- 当日文件：`records/YYYY-MM/YYYY-MM-DD.md`，日期是整理日期。
- 没有宿主会话 ID 时，不要把自己生成的 ID 冒充会话 ID。

## 配置

见 [配置模板](../templates/config.toml)。`projects` 和 `sources` 均可为空。配置不是 Codex、ZCode 或 Qoder 的原生配置。

- `format = "xmemory/v1"`：文件格式名，与插件发布版本分别管理；1.1.0 在这个名下定义了本文的布局。
- `capture`：`"explicit"` 只在用户要求时记录；`"milestone"` 另在被纠正、说明偏好、做出决定和阶段交接时记录。
- `[projects.<id>]`：`name`、`owner`，可选 `repo`（Git 远程地址）和 `paths`（候选位置列表，不区分机器）。项目身份优先看项目根 AGENTS.md / CLAUDE.md 中的“XMemory 项目 ID”。
- `owner = "xmemory"`：结果放在集中根内的 `projects/<id>/`；`owner = "external"`：用 `entry` 指向既有维护者的入口，不在本库写影子项目结果。
- `[sources.<id>]`：`scope`、`kind`、`path`、`enabled`，会话可加 `reader` 说明。`scope` 为 `personal` 或 `project:<id>`，项目须先登记。`kind` 为 `memory`、`session`、`files` 或 `results`，只帮助选择读取方法，不代表证据等级。

路径使用绝对路径或 `~`。来源路径只在某些机器上存在是正常的：本机不存在就跳过并注明。空路径、禁用来源不读取。来源不能指向 XMemory 结果目录形成自循环；研究 demo 和其他既有资料只有在用户明确选择时按资料接入。

## 入口

使用 [入口模板](../templates/MEMORY.md)。`## Index` 上方只放每次会话都需要的少数一行条目；索引每条写主题、一句结论或何时读取，以及真实相对链接。根入口另列各项目入口和根近况。只列已经存在的文件。

入口只由整理修改。记录新建的记忆在整理收录前也能被找到：调取时对照 `notes/` 目录和入口索引，读取尚未收录的新文件标题及 `links`、`valid_from`、`status` 等关系头部。

## 记忆

使用 [记忆模板](../templates/note.md)。一个文件围绕一个稳定主题和主张，不要求每一句话单独成文件。

| 字段 | 要求 |
|---|---|
| `identifier` | 必填，等于文件名主干 |
| `title` | 必填，一句话主题 |
| `tags` | 必填，含一个语义类型：事实、偏好、决定、经验；可加主题标签 |
| `status` | 必填：有效、待确认、已替代、已撤回 |
| `created_at`、`updated_at` | 必填，真实时间与时区 |
| `valid_from` | 何时开始适用，与记录时间分开；未知写未知 |
| `review` | 可选，到期复查日期 |
| `provenance` | 必填，谁写的：用户指示、助手、整理、导入 |
| `evidence` | 必填，依据的地址；无持久地址时写明原因 |
| `links` | 可选，如 `{rel: supersedes, target: <旧 identifier>}` |

正文写一个清楚的主张，保留否定和条件，再写适用条件与例外。经验还应保留已知的处理、结果、例外与证据；不知道不要凑字段。

`supersedes` 的目标须存在、范围相同、关系无冲突且已生效，新记忆才优先于被替代的旧记忆；整理时按 [更正规则](corrections.md) 标记状态并更新入口，定时整理不合并正文。普通更正记录旧结论与新依据；敏感信息撤回按专门规则清除，不以历史保留为由复述。

## 事件文件

使用 [事件模板](../templates/record.md)。头部必填 `identifier`、`recorded_at`、`event_at`、`provenance`、`evidence`；可选 `line`（工作线）、`context`（分支、提交、环境、草稿或正式等适用条件）、`artifacts`（相关文档或代码的地址），有两个载体时再加 `primary` 和 `synced`。

正文写目标与变化、已确认与待确认、未完成与下一步；计划、助手自述和已核实结果分开。不复制完整对话或工具日志。

记录时间决定文件名和存放位置；历史事件保留真实事件时间，不因现在采集而改写发生日期。事件文件建立后不再修改；后续发现错误时新建一条更正事件并指向原文件，不伪装成当时已知。采集的事件注明本次实际读过的来源和未读边界。

“某段时间发生了什么”按 `event_at` 归属；`recorded_at` 是记录时间，当日文件日期是整理时间，三者不能互相替代。历史回顾需在指定范围按各月事件清单检查头部，包含未整理及后来采集的事件，不仅限于对应日期的当日文件。`event_at` 未知时保留未知并说明，不能推定发生于记录或整理当天。

## 近况

使用 [近况模板](../templates/CURRENT.md)。写明截至时间、本次读过和未读的来源；按工作线分节，每节写目标与已确认进展（实现、测试、部署、验收分开），待办用稳定行动 key，例如 `verify-deployment`。

近况只由整理整篇重写。每条旧待办要么还在新近况里，要么在当日文件的“状态变化”中写明去向和依据。连续 3 次成功记入当日文件的整理都没有新依据的待办移入积压，近况只留数量和指向；失败重试、残缺登记和无变化零写入不累计次数，证据不足以数清轮次时保留并说明，不猜次数。个人近况只概述跨项目重点并链接项目近况。

“待确认建议”放定时整理产出的判断类改动，每条保留原事件或记忆地址。建议成功保存后，其来源事件可以登记为已处理，但建议尚未获准执行。下一轮重写继续保留未处理建议；接受、驳回、撤销或被替代时，在当日文件记下去向和依据。不因本轮没提到而删除，也不在重试时重复新建。

## 当日文件

使用 [当日文件模板](../templates/day.md)。先保存需要变化的记忆、积压、墓碑、近况和入口并回读确认，最后在当日文件末尾追加一节“HH:MM 整理”：处理的事件、决定与冲突、状态变化。每个已处理事件独占一行，包含明确相对链接和已保存的去向（更新近况、形成记忆、登记待确认建议或无需收录），需要时链接结果。不改已有的节；文件不存在才新建。没有实际处理结果或状态变化时不生成空节；读取失败可以零写入并报告缺口，只有核对完整且无变化时才回复“本次无变化”。

“已处理”表示本次整理结果已保存，不表示相关业务已完成或事实已核实。写入或回读失败时不提前登记；当日文件只追加了一部分时，重试核对完整条目、补缺失条目，不重复完整登记，不把残缺条目作为处理凭据。业务状态和执行顺序见 [共同约定](contract.md#写入规则)。

未处理事件按当前范围计算：列出 `records/` 各月的事件文件，扣除该范围所有当日文件“处理的事件”中的明确引用及撤回标识明确匹配的内容。链接按所在当日文件目录解析后与事件路径核对，不只比较短名；“决定与冲突”等其他段落中的提及不算处理。旧格式中含明确事件链接和处理说明的完整登记仍有效，不批量改写旧当日文件。

近 30 天只决定正文阅读优先级，不限制未处理事件的识别。先比较文件清单和处理登记，再按当前问题与时间展开必要正文，不要求把全部历史读入上下文，也不扫描其他项目或原生来源。用户明确限定时间范围时遵守并说明；事件较多、部分未读或登记无法核对时，报告剩余范围与缺口，不把未知当成已处理或宣称“本次无变化”。

## 积压

使用 [积压模板](../templates/BACKLOG.md)，只在第一次移入时创建。每项一行：行动 key、移入时间、最后依据、原因。有新依据时由整理移回近况，并在当日文件记下。

## 撤回标识

`WITHDRAWN.md` 只在撤回时创建，用 [撤回模板](../templates/WITHDRAWN.md)。每行保存条目 ID、可安全保留的来源地址、撤回日期、执行者和不泄露内容的原因，阻止同一来源自动复活；不重复敏感原文。详细处理见 [更正与撤回](corrections.md)。

## 地址

| 类型 | 写法 | 在别的机器上 |
|---|---|---|
| 库内文件 | 相对路径 | 记忆库整体同步，到哪都在 |
| 项目文件 | `project:<ID>/<相对路径>`，可加 `@heading=<标题>` 或 `@<提交号>` | 本机有该项目就拼出路径；项目在 GitHub 上可用 `gh` 读取 |
| 云端对象 | `feishu:docx/<token>`、`gh:owner/repo#123`、`hf:spaces/<owner>/<name>`，可加 `@rev=<版本>` | 用对应命令行工具现查 |
| 只在某台机器上的 | 绝对路径或 `~/...` | 找不到就说明不在这台机器上 |

会被整体重写的文件（例如各客户端的聚合记忆）用 `@heading=<标题>` 定位，会话用 `@session=<ID>`，不用裸行号。云端对象只存稳定 ID，不存签名链接、临时预览链接或凭据。

## 长度与链接

入口短，近况够用，详情可展开。不设置历史总容量或重写比例。文件过长时先拆独立主题并更新链接，不压掉条件、来源和未决问题。本库内链接使用相对路径。
