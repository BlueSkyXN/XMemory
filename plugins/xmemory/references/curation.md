# 整理细则

整理相当于 Codex 的第二阶段合并、QoderWork 的反思、OpenClaw 的 Dreaming：由用户或宿主定时任务触发，一处执行，把足迹加工成意识、主记忆、主题、每日记忆和画像。证据等级与出处规则见 [共同约定](contract.md)，文件格式见 [文件格式](storage.md)。

## 1. 找出要处理的内容

1. 在指定范围逐个日期目录比对：`daily/<日期>/` 下存在、但 `daily/<日期>.md` 的“已吸收足迹”里没列出的文件，就是未整理足迹。不按年龄排除；近 30 天只决定阅读优先级。
2. 另外检查：`topics/` 中尚未收进 `MEMORY.md` 的主题；声明了 `supersedes` 的主题；`review` 已到期的主题；同步工具留下的冲突副本（文件名带 conflicted、副本编号等）。
3. 先比较清单，不一次读入全部正文。范围太大时按日期分批，未处理部分写进整理记录的“未完成范围”。
4. 没有未整理足迹、来源进度也没有变化时，回答“本次无变化”，不写任何文件。

## 2. 候选归一

把足迹和原生记忆中的内容拆成单条主张再比较，每条明确：

```text
对象：稳定的业务对象或主题
主张：事实 / 偏好 / 决定 / 做法 / 经验 / 坑
范围：personal 或 project:<项目名>，以及适用路径或阶段
观察时间：来源被观察的时间（不是整理时间）
状态时间：可变状态所代表的时间
依据：地址 + 出处类型 + 证据等级
边界：依据不能证明什么
```

先统一术语、日期和名称，再去重。相对日期换算为绝对日期。

## 3. 处置

每条候选只能选一个去向：

| 处置 | 何时用 |
|---|---|
| 合并已有 | 已有主题表达同一主张；补来源、修范围、补边界，不新建同义主题 |
| 晋升主记忆 | 满足第 4 节的晋升条件 |
| 留在意识 | 当前状态、近期冲突、待处理、可能日后晋升的内容 |
| 留在每日记忆 | 有意义的变化或决定，主要价值是时间线 |
| 待核实 | 当前任务依赖、但只有原生记忆或 AI 汇报支持；写明还缺什么证据 |
| 退役或改写 | 已有主题过时、被推翻、范围错或无法回查 |
| 丢弃（重复 / 临时 / 无关 / 敏感） | 已被更强证据覆盖；修订号、计数、临时负责人、一次性状态；其他项目或无关内容；凭据、隐私 |
| 冲突 | 说法互相矛盾；不静默择一，在意识“冲突与未知”写双方依据 |

大多数观察到的事件只需进每日记忆；已有项目产物能回答的，只留地址。

## 4. 晋升到主记忆

满足以下任一条件，主题才能是“有效”：

1. 亲自读到的用户原话（当前对话或原始会话）明确表达了偏好或决定，按原话限定的范围晋升；
2. 至少两条独立证据支持同一条主张，来自不同会话、日期或客户端；同一段话的多处转述只算一条；
3. 亲自读到的执行结果（测试输出、部署输出、回读）支持的事实。

一个主题含多条主张时（例如把不同会话的不同教训合成一份清单），逐条判断：每条都满足上述条件，主题才是“有效”；一个来源支持 A、另一个来源支持 B，不算两条证据。有一条不满足，就整体写“待确认”，或者把满足的部分拆成单独主题。

只有原生转述或 AI 汇报支持、但有复用价值的内容，可以建主题，但 `status` 写“待确认”，主记忆要点末尾标“（待确认）”，并在 `sources` 里写明缺什么证据；也可以只留在意识的“记忆候选”。之后回原件读到用户原话或执行结果，或出现第二条独立证据，再改为“有效”。

另外：

- 晋升前回到至少一处原件核对；原件不在本机时说明，按待确认处理。
- XMemory 自己生成的意识、每日记忆和 `state/` 内容不算证据。
- AI 的结论或推荐只能记成“AI 汇报”，不能写成用户决定。
- 可变计数、修订号、负责人和运行状态不进主题。
- 已有 `AGENTS.md`、Skill 或正式规范承载的流程，主题只存入口和例外。
- 范围从窄：在某个项目里说的偏好或做法，先放在该项目。只有用户明确说“所有项目”“以后都”，或同一偏好已在两个以上项目独立出现，才进 personal；不能凭“听起来像通用要求”自行扩大。

## 5. 放置与分工

| 层 | 写什么 |
|---|---|
| 每日记忆 | 那天发生了什么 |
| 意识 | 现在该知道什么、该做什么、什么没定 |
| 主记忆与主题 | 以后还会用的规则、决定、做法和坑 |
| 画像 | 跨项目适用的用户背景与协作偏好 |

同一事实在不同层用不同粒度表达，不逐字重复。同一主张出现在多个客户端时只保留一条，挂多个来源。

## 6. 重写意识

1. 重写前把当前 `AWARENESS.md` 原样复制到 `state/history/<范围>/AWARENESS-YYYY-MM-DD.md`（同一天再次重写加 `-HHMM`）；删除超过 7 天的副本，并保持最多 10 份。
2. 整篇重写，不在末尾追加。近期信息优先刷新状态；更早的明确决定不会因为最近没提而删除。
3. 逐项核对旧“待处理”：保留、完成、取消、被替代、移入搁置或待确认。每项要么在新版中，要么在当天每日记忆或整理记录里写明去向和依据。没有近期消息不等于完成，也不能缩小原目标来宣称完成。
4. 常规改写幅度为 30%–70%。重写后与副本比对，粗估每节的改写比例并写进整理记录：
   - 低于 30%：检查是否漏读近期足迹；
   - 高于 70%：逐项核对“待处理”和“冲突与未知”有没有被误删。
5. 超过容量时：
   - 按 `[低]` → `[普通]`、同级最老的先移出；
   - 稳定内容晋升主题，已完成的移入每日记忆；
   - `[关键]` 条目只在用户确认后移出；
   - 每项移出都在整理记录里写明去向；
   - 不静默截断。
6. personal 的意识只写跨项目重点并链接各项目意识。

## 7. 维护主题与主记忆

- 合并到已有主题时保留 `name`，补 `sources`、修正 `applies_to`，更新 `updated`；不新建同义主题。
- 主题被推翻：新主题写 `supersedes`，旧主题状态标为“已替代”；替代目标须存在、范围相同、没有竞争或互相替代的冲突、新主题已生效。不满足时保留旧主题，在意识“冲突与未知”登记。
- 到期复查：更新、缩窄、待确认或退役，不机械延期。
- `MEMORY.md` 要点由整理根据主题的 `description` 生成或修订；不一致以主题文件为准。新主题收进对应分组。

## 8. 写入顺序与核对

1. 冻结本次范围（参与整理的日期与足迹清单），之后出现的新足迹留到下一次。
2. 存意识副本。
3. 写主题、积压的待确认项、撤回标识。
4. 写主记忆要点、画像、意识。
5. 重写涉及日期的每日记忆，末尾列出已吸收足迹及去向。
6. 回读核对，三项都要做：
   - **关键信息保全**：旧待处理和冲突条目中的路径、ID、版本号、数字、日期，在新版中要么还在，要么有去向；
   - **已有条目损失**：旧主题和主记忆要点，要么保留，要么写明处置（合并、退役、改写），不能无故消失；
   - **日期绝对化**：新写的内容里没有未换算的相对日期。
7. 在 `state/curation/YYYY-MM.md` 追加本次整理记录（[模板](../templates/curation.md)），再推进 `state/sources.md`。

任一核对失败：修正后再登记；无法修正时停止当前范围，不把相关足迹列入“已吸收足迹”。

## 9. 退出

- 根配置缺失或记忆库不可达：整次停止。
- 发现另一处正在整理同一范围：停止该范围。
- 目标文件在写入期间被改：重读核对；持续冲突、写入失败或回读不符时，停止当前范围的后续写入。
- 重试按足迹路径、主题名、行动 key 核对已有结果，只补缺失步骤。
- 有剩余未处理足迹、读取缺口或写入失败时，不宣称全部完成或“本次无变化”。
