# 更正与撤回

先确认本次要求及范围。报告错误不自动授权批量删除；明确“更正这条、忘记这件事”允许处理对应 XMemory 内容，不包括原生客户端、备份和外部系统。正文更正和撤回都由手动整理执行；定时整理只登记待确认建议，以及下述已声明替代关系的状态变化。

## 更正

按稳定 ID、主题、来源查到旧条目，读取完整条件，检查引用它的近况、入口与其他条目。保留适用范围，更新当前结论，必要时记录替代关系和更正时间。

记录在对话中收到纠正时只新建一条记忆，并在 `links` 中声明 `{rel: supersedes, target: <旧 identifier>}`。整理先核对目标存在、范围相同、各自适用条件及新条目的生效时间，且没有竞争或相互替代的冲突。关系明确且已生效时，定时整理只标记旧条目“已替代”、更新必要元信息及入口，不合并或改写两条记忆正文。合并必要内容只在手动整理的授权范围内执行。

目标缺失、声明冲突或新条目尚未生效时，不强行替代；整理保留旧条目并在近况登记带来源地址的待确认建议。调取在整理前也核对这些条件：即使旧条目仍标“有效”、入口尚未更新，关系明确且已生效时也采用新条目；未来生效时当前继续采用仍有效的旧条目，并说明切换时间；竞争或相互替代的冲突说明双方依据，不按文件新旧选择。调取全程只读，不代替整理更新状态。

事件文件建立后不再修改。事件内容有误时新建一条更正事件并指向原文件，不改原文件。

只是用户偏好变化，就说明从何时采用新偏好（`valid_from`），不说过去从未有过旧偏好。客观状态发生变化要有对应结果，不能用偏好修改替代事实验证。

## 忘记

1. 定位本次要撤回的内容及本库内派生摘要，包括相关事件文件、当日文件和近况。只处理明确范围，不扩大到其他主题。
2. 清除活动正文和派生内容中的被撤回信息；需要保留文件身份时用不含原文的简短撤回标记。整文件仅包含该内容且用户明确要求删除时，可以删除该文件并修正入口；操作前读取确认没有混入其他事件。撤回是唯一允许修改已有事件文件的情况。
3. 在范围内的 `WITHDRAWN.md` 记录条目 ID、可安全保留的来源地址、撤回日期、执行者和不泄露内容的原因，不复述敏感内容。若地址本身泄露该信息，则使用不含敏感含义的本地 ID 并说明匹配能力降低。
4. 后续采集或记录遇到相同 ID 或来源，不自动重收录。用户现在明确要求恢复时按新请求处理并记录恢复关系；身份不明的相似内容不能声称已经可靠拦截。
5. 回报实际清除范围和未覆盖部分。不要新建包含被遗忘原文的备份。

如果用户要求连阻止重收录的标识也完全删除，按其明确范围处理，并说明以后无法依靠该标识阻止旧来源被再次采集。

## 边界

纯文件约定不提供物理擦除、备份清理、云同步删除或原客户端删除。原始资料可能仍存在；不能承诺“所有地方都已忘记”。记忆库若用 Git 仓库同步，历史提交里仍有原文，需要彻底清除时要另行处理历史并说明影响。链接索引是辅助，处理派生内容时还要按相关主题和来源定向搜索本库，避免漏掉正文引用。
