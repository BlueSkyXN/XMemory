# 目录、配置与格式

本文是 `xmemory/v1.5` 文件契约，供技能与后续 `status` 共同使用。记忆正文用 Markdown，配置用 TOML；不额外保存扫描进度或运行状态。

## 目录

```text
<记忆根>/
├── config.toml
├── memory_summary.md
├── USER.md
├── records/
│   ├── sessions/<客户端>/<YYYY-MM>/<YYYYMMDD>-<主题>-<会话ID尾8位>.md
│   ├── imported/<客户端>/<YYYYMMDD>-<主题>.md
│   ├── files/<项目>/<YYYYMMDD>-<主题>.md
│   └── notes/<YYYYMMDDTHHMMSS>-<主题>.md
├── daily/<YYYY>/<YYYY-MM-DD>.md
├── projects/<项目>/
│   ├── AWARENESS.md
│   ├── MEMORY.md
│   └── topics/<主题>.md
├── personal/                       结构同项目
└── .xmemory/backups/                整理前副本，可丢弃，不参与采集
```

日期按配置时区解释。一个会话跨日有多份记录，同日重读更新原文件；文件类记录使用初次确定的起始日期和主题，不随每次采集日期换文件。同一主题的来源身份不同则分别命名，冲突时加有依据的区分后缀；ID 尾八位只用于文件名，完整身份放在记录里。

内容属于同一项目时归入该项目；会话跨项目或汇总材料有多个明确项目时，记录的 `projects` 可包含多项。空列表表示确实不属于项目的 personal 内容，不把尚未判定归属的项目材料默默归到 personal。

## 配置

从 [config.toml](../templates/config.toml) 填写，模板中的来源默认关闭。

| 字段 | 含义 |
|---|---|
| `format` | 固定 `xmemory/v1.5` |
| `timezone` | 实际使用的 IANA 时区；模板 UTC 只是可解析的示例 |
| `exclude_sessions` | 本库采集及联合查阅都须排除的完整会话身份列表，使用下文的 `client:<原生 ID>`，不用标题或 ID 后缀；不表示已删除原生副本 |
| `[sources.<名称>]` | 每个可选择来源的 `enabled`、`kind`、`client` 和 `paths` |
| `sources.*.kind` | `sessions`、`memory` 或 `files`；当场笔记不需要外部来源配置 |
| `[projects.<项目名>].roots` | 项目实际路径及已确认的 worktree/别名路径 |
| `[limits].awareness_max_bytes` | 可选的意识文件 UTF-8 字节上限；未设置就只报告实际大小与上限未配置 |

`paths` 是用户选定的明确目录或文件，不当作 shell 表达式执行。项目根采用路径边界匹配，多个匹配取最具体的根；根以外的材料按内容和来源核实归属。客户端名称用于来源标注，不意味着当前已安装该客户端或读取器。

全局摘要固定不超过 10,000 字节；项目完整整理由客户端每 7 天触发，也可由用户随时要求。库中不保存上次整理时间，不从索引的 `updated` 推算周期。

## 共同 frontmatter

所有对象都有以下三项，值使用单行带引号的字符串。列表用一行字符串数组；不用 YAML 标签、别名或嵌套对象，保持普通工具易读写。

```yaml
---
format: "xmemory/v1.5"
kind: "record"
updated: "2026-10-12T18:00:00+08:00"
---
```

上面的时间仅为格式例子，实际文件必须取系统时间。`kind` 取 `record`、`daily`、`project-index`、`topic`、`awareness`、`user` 或 `summary`；索引与主题共同组成一种“项目总结”对象。

`updated` 表示本次实际保存或完整复核时间。使用带时区偏移的 ISO 8601 时间，不靠 mtime 判断语义更新，也不把缺失时间当作零。正文有任何修改就用真实时间，不能保留旧值来隐藏修改；完整检查但正文无需改变时可以更新该值，不能只改时间消除尚未处理的来源提示。

局部同步一项明确更正也要更新真实 `updated`。这个字段不是全范围采集或吸收水位，不能据它排除尚未处理的记录；查阅需按主题与范围补查相关更正，`status` 的时间比较只提供机械线索。

派生对象未完成其本轮应处理的来源范围时，草稿留在当前上下文，暂不覆盖正式文件；对象之间可以分批完成。项目主题可分别保存，项目增量全部处理完才同步索引。记录可以保存已读部分，用真实时间和 `coverage: partial` 表达缺口。单纯格式修正也会触发下游复查，这比正文已变却没有更新信号更可靠。

## 记录字段

参照 [记录模板](../templates/record.md)。`updated` 是本次记录保存时间，不再另建提取进度字段；是否读全由 `coverage` 表达。

| 字段 | 填法 |
|---|---|
| `source` | 对应配置来源名称；当场笔记填 `note` |
| `client` | 来源客户端，项目文件可填 `filesystem` |
| `source_ref` | 读取器返回的完整引用；文件材料填完整原文件定位；无会话标识的当场笔记填 `current-conversation` 并说明缺口 |
| `source_location` | 原件路径及可用的行号、字节或数据库定位，照抄实际结果；源文件 ID 与原生会话 ID 不混用 |
| `source_updated` | 本次实际读取到的来源更新时间，注明依据；未知填空，不能用采集时间代替 |
| `evidence` | `primary` 原始对话/项目文件/当场笔记；`primary-summary` 有可信单会话身份与明确范围的模型提炼；`secondary` 主题记忆、跨会话汇总或无法核实单会话范围的摘要 |
| `projects` | 已核实的项目名数组；无项目内容为空数组 |
| `day` | 本记录归入的本地日期 `YYYY-MM-DD` |
| `day_basis` | `event` 表示原始事件日期；日期未知、按采集日归档时填 `captured` 并在正文说明 |
| `event_days` | 可选的非空日期数组，列出来源实际支持的事件日期；省略时沿用 `day`，不能按起止日期补造中间日期 |
| `session_refs` | 经核实的 `client:<原生 ID>` 列表，用于遗忘匹配；文件没有会话身份就留空 |
| `coverage` | 对本记录声明范围的读取覆盖：`complete` 或 `partial`；partial 在正文写出缺页、截断或不可读位置 |

`evidence` 描述材料形成方式，不按客户端品牌给可信度排序，也不保证里面每个断言为真。Codex 逐会话摘要通常属于 `primary-summary`，ZCode 主题带 origin 会话标记仍可能经过多会话编辑。用户原话可证明其偏好或决定；助手自述和模型摘要不能单独证明测试、发布或部署已经成功。字段取值保持兼容，不为改标签批量重写旧库；实际复查相关记录时按来源范围澄清。

会话记录的范围是一天；覆盖完整不表示整个多日会话都已处理。跨期来源文件仍生成一份记录，`day` 取已知起始日，`event_days` 列出有依据的各日（例如 `["2026-10-10", "2026-10-12"]`），正文按日期区分事实。同一记录可以关联多个日总结，不另外拆成多份来源记录。

事件时间缺失时使用 `captured` 归档并省略 `event_days`，不把导入日写成历史事件发生日。1.5.0 的单日记录无需重写；只有回查原材料确认了其他事件日才补该字段。字段为空或日期无效时报告问题，不能静默退回单日来掩盖遗漏。

## 会话身份

新增 `session_refs` 和 `exclude_sessions` 使用 `client:<经核实的完整原生 ID>`，如 `claude:example-session-01`。客户端沿用来源标识（`claude`、`codex`、`zcode`、`qodercn`、`workbuddy`）；不同客户端的相同 ID 不是同一会话。导入摘要按其原始会话客户端标注身份，不按存放摘要的客户端改写。

`source_ref` 保留读取器原样返回的引用（例如 `claude:jsonl:example-session-01`），`source_location` 保留原件路径与定位。只有从原件元数据或可信来源确认原生 ID 后才能填写会话身份；读取器的 `session_id` 可能退回文件名，不能仅删掉引用中间一段就认定是原生身份。子代理或迁移副本同样先核实，不按父会话或相似文件名合并。无法核实时留空并注明缺口。

已有读取器式身份按原字符串精确匹配，`status` 对可识别的旧形式给出 `identity_review`，不自动迁移，也不证明规范形状的 ID 已核实。维护时先验证对应关系，再同步记录和排除列表；排除列表保留仍可能遇到的旧引用，防止旧来源重新导入。

## 派生对象与来源链接

- [日总结模板](../templates/daily.md)：增加 `day`。按项目分节，会话块有 `<!-- session:<完整身份> -->`。文件或笔记没有会话身份时使用 `<!-- record:<根内记录相对路径> -->`。每块链接到记录。
- [项目索引模板](../templates/project-index.md)：只列主题、链接和什么时候看，不复制主题正文。本轮项目增量处理完后同步索引；完整整理另由客户端周期触发。
- [主题模板](../templates/topic.md)：一个文件多条；每条小节有类型、适用条件、关键词、来源、状态和依据日期。状态可为有效、待确认、已替代、已撤回。
- [意识模板](../templates/awareness.md)：当前认识、近期变化、冲突与未知、待处理、记忆候选五节；每条关键判断附来源。
- [画像模板](../templates/user.md)：每条偏好有日期、原话或忠实转述、适用范围和记录来源。
- [全局摘要模板](../templates/summary.md)：项目各一行，包含现状、最近事件日期和去哪看；链接 `USER.md`，通用经验保留出处。

库内来源使用相对 Markdown 文件链接，必要时加锚点；不只写标题或 ID。来源链接从当前文件计算，移动文件时一并修正。模板里的路径和时间占位需要替换，不能作为事实保存。

项目文件或会话原件可以位于库外，只作为定位文本保存在记录里；`status` 不越出记忆根检查它。外部来源的存续与变化由读取工序判断。
