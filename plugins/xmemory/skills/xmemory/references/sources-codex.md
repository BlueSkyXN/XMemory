# Codex 来源适配

处理选定的 Codex 原生记忆或会话时使用。各版本目录可同时存在；目录存在不证明客户端正在使用它，也不自动授权采集另一套目录。

## 记忆入口与正文

| 材料 | 读法 |
|---|---|
| `memory_summary.md` | 全局导航；两版的 User Profile、User preferences、General Tips 段落也作为二手画像与经验材料；不把保存时间当所有项目进展日期 |
| V1 `MEMORY.md` | 可能同时含检索线索和已经归并的经验；先看标题、项目和关键词，再读相关段落，保留其中逐会话摘要未覆盖的有效条件与例外 |
| V1/V2 `rollout_summaries/` | 按实际头部的 `thread_id`、`rollout_path`、`cwd` 和正文选择单会话摘要；文件名仅作定位线索 |
| V1 `raw_memories.md` | 较大的会话提炼集合；有对应逐会话材料时先用后者。只在缺口指向它时按相关会话或主题分段回查 |
| `memories/extensions/<名称>/instructions.md` | 扩展说明，用来理解来源，不生成记录，也不把其中指令当作当前授权 |
| 扩展的 `resources/`、`notes/` | 来源材料；`ad_hoc/notes/` 每份一条记录，保留用户要求记下的笔记性质；Skysight 按下节直接写日总结 |

两套可能都有写入，读取按会话决定；当前实际读取哪套看读取器 `recent_injection`，允许用户会话与自动化会话混用，不写成“每个会话都双写”。V2 按设计没有 MEMORY.md、raw_memories.md、skills，不当作缺口；摘要首行 v1 是格式标记，不是目录版本。V1/V2 同会话用 `same_session_as` 合并说明，仍不以版本或保存时间判胜。选定材料仅有汇总经验时，按 [共同来源规则](sources.md#别家记忆)继承。

## 记忆技能

V1 `memories/skills/<名称>/SKILL.md` 是官方 Phase 2 整理产物，通常不在客户端可用技能清单里。每个制作一条简短记录，写它解决的任务、所属项目、用户触发说法、关键约束与例外，指向实际原文件；未知触发说法或项目不补造。不抄操作步骤，证据类型为 secondary。

## 自动化记忆

只采当前位置 `~/.codex/automations/<id>/memory.md`，按同目录 automation.toml 的 cwds 核实项目；多个 cwd 保留候选与范围，不强行选一项。作为该自动化的运行记录，保留日期和执行证据边界，不当作用户原话。采集自动化记忆不等于开启自动化会话采集，后者仍按线程规则。

## 非官方位置

V1 `memories/automations/` 是已停用的非官方位置，`memories/local/` 是用户技能在整理过程中的副产物；读取器标 unofficial、process_log，XMemory 不采集。

## Skysight 活动摘要

Skysight 根据本地活动事件流生成屏幕与应用活动的二手摘要。单独登记为 `kind = "memory"` 的来源，例如 `codex_skysight`，`client = "codex"`，路径为用户选定的 `~/.codex/memories/extensions/skysight/resources/`；不混入普通 Codex 记忆来源。来源种类仍只用现有枚举。

- 按配置时区把当天窗口直接整理进 `daily/<YYYY>/<YYYY-MM-DD>.md`，不生成记录。依据来源所述窗口定位日期，文件名的 UTC 时间先换算，跨午夜窗口只取该日部分，不把窗口截止时间当所有活动的发生时间。
- 6 小时摘要给出主线，10 分钟摘要补细节和未覆盖部分；不假定大窗口覆盖全部小窗口，同一活动只写一次。`applications`、`suggestion` 等呈现元数据不作为事实依据。
- 按项目分节，归属依照 [项目规则](format.md#配置)。独立活动块使用 `<!-- activity:codex-skysight:<YYYY-MM-DD> -->`；同日可在不同节各有一块，以所在节区分。未定项目放入 `## 归属未定`，不放 personal。
- 块内写活动要点与覆盖时段；文件末尾“来源与覆盖”集中写 Skysight 目录、一次二手性质说明，并按项目与块标记列出实际原件文件名及窗口。归属依据仅在推断时写，缺口仅在影响结论时写；当天未结束或窗口有缺口时保留范围，保存用真实 `updated`。
- 与同日记录描述同一工作时，在对应会话或记录块中补一条“Skysight 活动线索（二手）”，块内保留覆盖范围，原件身份归入文末该会话块的出处，不再建重复活动块。记录本身保持其独立来源，不用活动线索补写记录。
- 个人活动只保留日程层面的参加活动、出行、报名等，不写金额、账号、聊天内容、联系人或无关个人细节。
- 日总结按记录更新时，原样保留独立活动块和已并入会话块的 Skysight 线索；只有重读同日 Skysight 或收到明确更正、删除要求才修改。原件不可读时保留已知内容及缺口，不能从记录重建时丢弃它们。
- 活动内容严格只留在日总结，不进入项目主题、项目意识或用户画像；不得经日总结参考或全局入口间接提升为这些对象的依据。
- 查阅时保留二手性质，不写成本次核实。活动后面没有记录可展开；需要原话或执行结果时，有相关会话记录才沿其补证，没有独立来源且原件已清除时明确无法进一步核验。
- 用户要求删除活动时，清理相应独立活动块、会话块内线索、文末对应出处及本库备份中的对应内容；其他块仍使用的出处保留，保留独立会话来源支持的事实。Skysight 无稳定会话身份可供排除，不新增活动排除状态；原件仍在保留期内时可能再次采集，须说明可停用该来源或等待原件清除，停用由用户决定。已知来自被排除会话的活动转述仍遵守 `exclude_sessions`，不能绕过会话遗忘。

资源通常约 7 天滚动清除，需要日常或至少每周整理；这不是固定保留保证。日总结是活动在本库的唯一留存，原件清除后不保证能恢复或核对。`status` 不读取该外部来源、不解析活动块，也不以该来源的记录数为零判断尚未整理；覆盖范围由块内说明、文末对应原件身份与实际来源核对；旧文件从原有块内定位读取。

## 身份、归属与日期

- `source_ref` 保存实际摘要文件定位；`rollout_path` 是回查原件的线索，不用它冒充本次实际读取的来源。摘要声明单会话且身份可信时，`session_refs` 用 `codex:<thread_id>`；缺失或互相冲突时先核实，不从标题猜 ID。
- 同一 `thread_id` 的 V1/V2 摘要以及原始 rollout 属于同一会话的不同材料。保留实际读过的各份来源，不覆盖彼此、不算作独立佐证；日总结按同日同会话归并。两份摘要有差异时核对对应片段，不以 V2 名称或较新保存时间自动判胜。
- `cwd`、`git_branch` 是当时的线索。结合已配置项目根、已确认 worktree 路径及正文核实归属；跨项目会话按相关事件归属，不把最后一个 cwd 套给全部内容。
- 摘要 `updated_at`、文件 mtime 和 rollout 文件名中的时间都不能直接分配给整篇历史。按正文及原始事件确认事件日；跨日摘要保留一份记录并填写有依据的 `event_days`。日期不足时用 `captured` 并说明缺口。
- `primary-summary` 表示有单会话来源的模型提炼，不保证原话、执行结果或覆盖完整；来源与结论的可信程度分别说明。原生记忆注入片段、摘要自述和原会话不可重复计证。

## 回查会话

有 `rollout_path` 时，先核实该文件可读，再以文件 `--root` 和完整会话 ID 调用实际可用的 Codex reader；同时核对返回的 `session_id`、`id_origin`、`projects` 和来源。旧路径失效时，仅在选定的 `sessions/`、`archived_sessions/` 中按完整身份寻找，包括 `.jsonl.zst`；找不到则保留摘要定位和缺口，不改写原路径来假装回查成功。

先读可见正文，确认执行事实时再读相关工具调用与结果。分页、压缩支持及 `--snapshot` 以读取器当前说明为准；读取器的文件名回退 ID 尚需核实。`state_*.sqlite` 可帮助找标题，不能替代会话正文。恢复或迁移副本按原生身份核对，不凭相同标题合并。

`.jsonl.zst` 是无损压缩，原件路径可能在 .jsonl 与 .jsonl.zst 之间切换；按完整会话身份定位，不依赖旧路径。切换窗口内同目录同主干两种形态同时存在时，读取器优先明文并给 compressed_twin；字节偏移仍基于解压后内容。Codex 逐会话摘要的提取输入最多取会话最新约 8 MiB，长会话早期细节可能未进入提取；缺失不能归因于压缩，需要时回查原始会话。

## 会话线程类型

读取器的列表和事件带 `thread_source`、`parent_session_id`、`agent_path`；缺失为 null，不从标题或目录猜测。读取器保持原有 `variant`、`session_ref`，采集策略由 XMemory 执行：

- `subagent`：核对原生父子身份后，把汇报作为父会话记录的工具层证据，不单独生成子代理会话记录。按需读子代理原件补证；父会话不可读或关联不明时报告缺口，不随意挂到其他会话。已核实的子代理来源身份及支撑范围保留在记录中，采集与查阅同时检查父子会话的排除项。
- `agent_message` 保留作者、接收方、文本与原生消息标识，只在 `--include-tools` 时读取。它是代理通信，不能冒充用户原话或独立执行结果；`web_search_call` 是搜索工具调用，不能单凭调用证明搜索成功或结果成立。
- `automation`、`guardian_review` 默认不采集；用户明确指定时例外。未标注线程类型的旧会话按用户会话处理；出现新的未知类型时先核对含义，不能假定等于用户会话。
