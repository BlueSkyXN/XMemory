# Codex 来源适配

处理选定的 Codex 原生记忆或会话时使用。各版本目录可同时存在；目录存在不证明客户端正在使用它，也不自动授权采集另一套目录。

## 记忆入口与正文

| 材料 | 读法 |
|---|---|
| `memory_summary.md` | 全局导航，定位项目、关键词和支持材料；不把它的保存时间当成所有项目的进展日期 |
| V1 `MEMORY.md` | 可能同时含检索线索和已经归并的经验；先看标题、项目和关键词，再读相关段落，保留其中逐会话摘要未覆盖的有效条件与例外 |
| V1/V2 `rollout_summaries/` | 按实际头部的 `thread_id`、`rollout_path`、`cwd` 和正文选择单会话摘要；文件名仅作定位线索 |
| V1 `raw_memories.md` | 较大的会话提炼集合；有对应逐会话材料时先用后者。只在缺口指向它时按相关会话或主题分段回查 |

不假设 V2 有 V1 的全部文件，也不因看到摘要首行 `v1` 就判定目录版本。选定材料中仅有汇总经验时，仍可按 [共同来源规则](sources.md#别家记忆)继承。

## 身份、归属与日期

- `source_ref` 保存实际摘要文件定位；`rollout_path` 是回查原件的线索，不用它冒充本次实际读取的来源。摘要声明单会话且身份可信时，`session_refs` 用 `codex:<thread_id>`；缺失或互相冲突时先核实，不从标题猜 ID。
- 同一 `thread_id` 的 V1/V2 摘要以及原始 rollout 属于同一会话的不同材料。保留实际读过的各份来源，不覆盖彼此、不算作独立佐证；日总结按同日同会话归并。两份摘要有差异时核对对应片段，不以 V2 名称或较新保存时间自动判胜。
- `cwd`、`git_branch` 是当时的线索。结合已配置项目根、已确认 worktree 路径及正文核实归属；跨项目会话按相关事件归属，不把最后一个 cwd 套给全部内容。
- 摘要 `updated_at`、文件 mtime 和 rollout 文件名中的时间都不能直接分配给整篇历史。按正文及原始事件确认事件日；跨日摘要保留一份记录并填写有依据的 `event_days`。日期不足时用 `captured` 并说明缺口。
- `primary-summary` 表示有单会话来源的模型提炼，不保证原话、执行结果或覆盖完整；来源与结论的可信程度分别说明。原生记忆注入片段、摘要自述和原会话不可重复计证。

## 回查会话

有 `rollout_path` 时，先核实该文件可读，再以文件 `--root` 和完整会话 ID 调用实际可用的 Codex reader；同时核对返回的 `session_id`、`id_origin`、`projects` 和来源。旧路径失效时，仅在选定的 `sessions/`、`archived_sessions/` 中按完整身份寻找，包括 `.jsonl.zst`；找不到则保留摘要定位和缺口，不改写原路径来假装回查成功。

先读可见正文，确认执行事实时再读相关工具调用与结果。分页、压缩支持及 `--snapshot` 以读取器当前说明为准；读取器的文件名回退 ID 尚需核实。`state_*.sqlite` 可帮助找标题，不能替代会话正文。子代理或恢复副本按各自原生身份处理，不因引用父会话或相同标题合并。
