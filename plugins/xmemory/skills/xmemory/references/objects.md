# 六类对象的工序

各对象按自己的直接来源更新。可以单独执行，也可以在同一轮选多个；相互参考的产物不是必须先完成的上游。字段和模板统一见 [格式](format.md)。

Skysight 活动只留在日总结，不作为项目主题、项目意识或用户画像的来源；这些对象参考日总结时也不采用其中的 Skysight 活动线索。

## 记录

**来源**：一个会话的一天、别家记忆的一个文件、一个项目文件，或一条当场笔记。

Codex 扩展的 `instructions.md` 不生成记录；Skysight 摘要直接写日总结，不生成中间记录。线程类型与例外按 [Codex 适配](sources-codex.md) 处理。

**更新条件**：新增材料，或核实来源比原记录所读版本更新；原记录 partial 时补读其缺口。

1. 对照完整来源身份找到已有记录，应用排除列表，读完本次声明的范围。会话需要执行依据时展开有关工具结果；文件按相关结构分段读取。
2. 写任务史：当时的目标、用户原话与纠正、必要经过、执行结果、改变过的决定和未决事项。静态文件写它能证明的项目事实，不编执行过程。
3. 保留对后续有用的路径、命令、版本和错误原词；去掉重复叙述、无关工具噪声与秘密值。区分建议、已采纳决定和已执行结果。
4. 保留来源定位、日期、证据层级和读取缺口。原始会话与别家摘要各自留记录，后续对象再合并相同结论。
   只有实际读过对应原件或原始事件，才能把本次结论写成“核实”“验证”“确认”；二手来源写“按摘要所引的窗口、路径或会话定位，未读原件”。可归属地转述原摘要的完成陈述，不把它升级为本次已验证。
5. 保存本记录时填写真实 `updated`；未读全则保留已有完整内容，补充已读部分并标 `coverage: partial`，不因来源暂时不可读删除旧事实。跨日文件按已知事件填写 `event_days`，仍只生成一份记录。

**完成结果**：一篇带出处的任务史。没有可复用经验也可保留必要经过；没有实质内容则不造记录，汇报已检查但未生成。不会因此生成单独的“已处理”标记。

## 日总结

**来源**：day 或 event_days 关联到该日的会话、导入、文件与笔记记录。跨期材料只摘当天有依据的内容，同一记录可被多个日文件引用；不把整段历史说成当天新做的工作。

选定的 Skysight 活动摘要也是直接来源，按 [活动摘要规则](sources-codex.md#skysight-活动摘要) 分日去重、标注覆盖范围与二手性质，不生成记录。

**更新条件**：当天有新记录或更新记录、选定的 Skysight 窗口需要整理，或已有块的来源被更正、遗忘。

1. 阅读当天相关记录，按项目分节，无项目内容单列 personal；带 `project_status: "unresolved"` 的材料单列“归属未定”。
2. 同一天同一会话一块，最多 8 条要点，突出当天的变化、结果与重要待办。同一结果的多轮操作、计数和验证合并表达，仅展开会改变当天结论的差异；细节从记录链接回查。同一会话的原件提炼与导入摘要合并到同一块并同时链接。
3. 没有会话身份的材料按记录成块，保留它是项目文件、当场笔记还是二手材料的区别。按采集日归档、没有事件日期的导入（`day_basis: captured`）列入“历史资料归档（事件日期未核实）”，每条一行写范围和链接，具体内容归入项目主题或画像，不写成当天工作。
4. 更新已有块并保留其他项目的有效内容。保存前检查当前 `status --summary` 中该日文件的 `newer_sources`、`unlinked_sources` 和结构问题；全部待更新记录在本次范围内且已处理完、没有阻断检查缺口时，才用真实 `updated` 保存。
5. 仅按记录更新时，原样保留独立活动块及会话块内注明来自 Skysight 的线索；只有重读同日 Skysight 或收到明确更正、删除要求才修改这些内容。原件暂时缺失或已清除不构成删除依据。

**完成结果**：能从一个日文件看当天各项目发生了什么。没有内容不建文件。指定只改某项目，而当天其他项目还有未纳入的新记录或更正时，保留日文件，先完成其他对象，并报告“日文件待整篇整理”。Skysight 的窗口与原件身份另按覆盖说明核对，不依赖记录链接检查。

## 项目总结

**来源**：该项目记录，日总结可作导航。日常更新聚焦新增或更正的记录及其涉及的主题。

**更新条件**：项目记录或主题有更新、主题仍待整理、存在未链接记录，或缺少索引。索引为 current 时也检查全部主题状态与 `unlinked_sources`。完整整理由用户要求或客户端每 7 天触发；库内不保存上次整理时间。

1. 日常增量读取索引、待整理记录和涉及的主题，识别可复用的决定、事实、做法、偏好、经验和参考。已链接记录更新看对应主题的 `newer_sources`，未被任何项目文件引用的记录看 `unlinked_sources`，不只依据索引时间筛选。复核后没有可复用结论的记录（例如导航索引）列入索引末尾“参考记录”，每条写原因，不为消除提示把它们提炼成主题。
2. 归入已有主题，必要时新建主题。每条先写可复用结论与适用条件，并给出什么时候用、关键词、来源和状态。历史步骤、文件清单和逐次测试数量留在记录中；仅当它们决定适用范围、能否采信或如何复现时摘入主题。版本、命令和错误原词按此判断保留，不因来源里存在就再次抄入。
3. 在本次涉及的主题中合并重复、处理替代关系和相对日期。完整整理时才遍历全部主题，检查索引、过时内容和跨主题重复。保留关键标识、例外和未解决冲突；“写得更晚”本身不是推翻旧结论的证据。判断两条结论的先后只用记录正文里的事件时间或 `day`；`source_updated`、`updated` 和文件修改时间表示版本，不表示事件先后。两边事件时间精度不同或缺失时，写“先后无依据”并并列。
4. 对被替代或撤回的内容保留必要指向和原因，避免查阅者把它当当前规则；明确遗忘的内容按遗忘工序清除，不保留其正文作历史。
5. 保存单个主题前处理完该文件所引用来源的全部待更新内容；若来源超出本次范围、尚未处理完或有阻断检查缺口，保留主题原文件并列为待整理。用户明确只要同步其中部分条目时也先不保存，说明其余更正会因此不再被提示，由用户选择一并处理或暂不保存。已完成主题保存后可随即更新 `MEMORY.md`：一行一个主题链接，加什么时候看，保留其他有效主题入口。

**完成结果**：已保存主题与索引一致；汇报完成的主题及剩余来源。明确的当场更正以新笔记为依据，仍遵守单个主题的保存条件。项目索引可以随已完成主题更新，其余过期主题与未链接记录继续处理。没有新内容时不为消除提示而重写。

## 项目意识

**来源**：该项目近期记录与旧意识中的未决事项；项目总结、日总结是可选参考。

**更新条件**：近期有新记录，现状被新证据改变，或旧待处理项有了明确结果。`status` 对新项目记录的提示只是候选，AI 判断其相关性。

1. 读旧意识，列出仍影响当前工作的判断、冲突与待处理项；从近期记录核对哪些已改变。近期范围跟随用户任务和读取范围，不用年龄自动删除旧未决事项。
2. 围绕当前判断和下一步，整篇重写五节：当前认识、近期变化、冲突与未知、待处理、记忆候选。近期变化只列改变当前判断的内容，相同证据边界集中说明，具体历史从主题或记录回查。空节可以写“暂无有依据的内容”，不凑事实。
3. 旧待处理项逐项有去向：继续保留，或有证据地说明完成、取消、被替代。去向可以写在新意识或相应记录里；不能仅靠助手曾说完成就消失。
4. 当前认识说明截至何时、依据在哪；候选还没有足够证据时留在候选，不提升为稳定规则。

**完成结果**：后来者能知道目前怎么看、哪里不确定、下一步是什么。用实际完成时间更新 `updated`；配置了大小上限时压缩表达，保留证据和未决事项。

## 用户画像

**来源**：各类记录中的偏好、纠正、工作方式，以及别家画像生成的导入记录。

**更新条件**：出现新的跨任务偏好依据，或已有偏好被用户更正；新记录只触发复查，不自动增加画像条目。

1. 区分长期要求与单次任务条件。“这次直接做”不能自动变成“以后所有任务都直接做”。
2. 用户明确说明以后沿用或更正的偏好，保存笔记后同步相关画像条目，不要求再次点名同步；用户只要记录时除外。局部同步核对该条目的旧来源、新要求和范围，保留其他条目，不代表已复查所有记录。从多次行为推断的模式标明推断和依据，不能冒充原话。
3. 每条保留适用范围、依据日期与记录链接。二手画像仍标明二手；与当前明确要求冲突时按新要求更正，保留必要解释。
4. 合并同义偏好，删除没有支撑的泛化。完整复查后，即使正文无变化，也可以更新 `updated`；不保存无关的个人信息。

**完成结果**：一份有证据且能改变后续协作方式的 `USER.md`。没有新内容不凑画像；对象不存在且无画像依据时可保持不存在。

## 全局摘要

**来源**：各项目与 personal 已有的意识、索引，以及 `USER.md`。

**更新条件**：任一上述来源比它新，入口缺失，或来源结构、链接被更正与删除。

1. 读本轮相关项目入口和画像，保留其他项目仍有效的入口。没有意识时可以从已有索引给出入口，缺什么就说明什么，不强迫先补齐其他对象。
2. 重写紧凑入口：每个项目一行，写有依据的现状、最近事件日期、意识与索引链接。不存在的目标不生成假链接。
3. 指向 `USER.md`，通用经验写影响多个任务的少量结论并带出处；不复制全部画像和项目细节。
4. 按 UTF-8 字节数控制在 10,000 以内，删重复说明和可从链接读取的细节，不以删出处换长度。

**完成结果**：一个能导航的全局入口。它是否相对库内来源更新，与外部客户端是否还有新内容是两件事；来源仍旧时不把整理入口当成核实了现实进展。
