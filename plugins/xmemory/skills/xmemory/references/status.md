# status 报告约定

本页说明只读检查结果。程序入口为 `scripts/xmemory.py --root <记忆根> status` ，其他操作由 AI 直接读写文件。退出码 0 表示已生成报告（报告仍可包含问题），2 表示库或配置无法读取。

## 范围

- 只读取指定记忆根内的配置与 Markdown，不扫描客户端目录、连接外部数据库或跟随链接越出记忆根。
- 不创建根目录、修文件、更新 mtime、写缓存、生成锁、登记运行状态或修改排除列表。文件系统自身是否记录访问时间不属于程序写入行为。
- `.xmemory/backups/` 不参与有效对象、数量、过期和来源起点计算；遗忘技能单独处理备份。
- 报告问题，不拦截其他技能写入；缺失、解析失败与未知不能混为“已更新”。

## 各对象怎么判断

| 对象 | 程序可提供的机械判断 | AI 仍要判断的内容 |
|---|---|---|
| 记录 | 字段、时间格式、partial 标记、是否命中排除列表 | 外部材料是否新增或变化、是否已读完整、正文是否忠于原件 |
| 日总结 | 根据记录的 day 找到候选日文件，比较该日所有记录的 updated | 哪些材料值得写、会话去重、跨期材料如何表述 |
| 项目总结 | 根据记录的 projects 比较索引；主题比索引新；索引距今超过 7 天 | 归入主题、合并重复、处理矛盾、退役过时内容 |
| 项目意识 | 项目记录中有比意识新的记录，提示复查 | 哪些属于近期并改变现状、旧待处理项是否有着落 |
| USER.md | 新记录、画像引用的来源变化，提示语义复查 | 是否包含跨任务偏好、是否有充分依据 |
| 全局摘要 | 项目/personal 的意识与索引、USER.md 比它新，或已有入口链接失效 | 现状是否准确、最近事件日期、如何压缩 |

比较候选来源时按日期和项目范围枚举记录，不能只检查已经链接的记录，否则新增而未链接的材料会漏掉。对象不存在时报告候选目标；没有有用内容是否需要新建由 AI 判断。

时间缺失、无时区、不能解析、明显晚于当前系统时间或来源包含 partial 时，报告未知或复查原因。`updated` 相等只表示按已有元数据未发现更新，不能证明语义正确。

## 报告字段

输出 JSON，字段名称作为报告约定；不额外保存该 JSON：

| 字段 | 内容 |
|---|---|
| `schema` | `xmemory/status-v1.5` |
| `root`、`timezone`、`now` | 实际检查的根、时区、当前带偏移时间，供 AI 在保存时使用 |
| `objects` | 每个已有对象或候选目标的 `path`、`kind`、`updated`、`assessment`、`reasons`、`newer_sources` |
| `source_hints` | 每个配置来源的记录数、已记录的 `latest_source_updated`、`latest_record_updated`、partial 数；外部覆盖固定注明未检查 |
| `issues` | 问题的 `code`、库内 `path`、可用行号与简短原因；未知字段值不回显为秘密 |
| `counts` | 按对象判断与问题类型汇总数量，用于前后报告 |

`assessment` 是本次计算结果：`stale`、`review`、`missing`、`current` 或 `unknown`。它不落盘，也不作为下轮任务状态。`current` 只针对已存在的库内来源及有效元数据；外部来源没有检查时不能据此宣称全库已经同步。

`newer_sources` 给出具体记录或项目文件的库内路径，不能只有一个总数。`source_hints` 以原来源更新时间和提取更新时间分别报告，不能把新导入旧材料的时间误当原会话活跃时间。

## 问题类型

- `broken_link`：库内 Markdown 目标不存在；不检查外部原件、URL 的可达性，不执行链接。
- `missing_field` / `invalid_field`：记录或对象字段缺失、身份与日期结构无法解释。
- `invalid_time` / `future_time`：日期或时区错误，不能可靠比较。
- `partial_source`：记录已明确注明读取缺口。
- `excluded_record`：有效记忆中仍有被配置排除的会话记录，或可机械识别的会话身份残留；程序不代替语义清理。
- `suspected_secret`：仅报告文件、行号和匹配类型，不输出命中值或邻近原文。
- `oversize`：入口超过 10,000 字节，或意识超过用户配置上限。意识上限未配置时报告实际大小与 `limit_unset`，不把它算作超限。
- `read_error` / `unsupported_format`：本次读不到或不能理解的库内文件，保留其他正常结果并报告检查缺口。

## 验收依据

用隔离的合成库验证：新增未链接记录能触发对应对象；只改 USER.md 会使入口过期；topic 比索引新会被发现；对象缺失与元数据无效不会算作 current；最大来源时间不被表述成覆盖完成；部分输入保留检查缺口；秘密报告不回显值；命中排除列表与断链可定位；时区跨日和超过 7 天的边界正确。

只读性需要比对调用前后的文件清单、内容及修改时间，并验证不会创建缺失的库或 `.xmemory/`。自动测试覆盖这些程序行为；它不验证模型整理的语义质量。
