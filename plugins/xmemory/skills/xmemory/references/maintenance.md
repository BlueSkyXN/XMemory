# 更正、恢复与遗忘

## 更正与影响当前结论的变动

为避免“笔记已写但主记忆仍旧”，使用入口已有 Markdown 中的短提示，不建队列或隐藏目录。

1. 在 `memory_summary.md` 的 `## 待处理` 下，先保存本项范围与明确的新要求或材料支持的变化；待核查事项保留具体未知，未采纳方案保持候选。有笔记后可补相对链接，提示本身须能独立说明变化与适用范围。
2. 保存或更新相关 notes。用户要求整理时，再局部更新 `MEMORY.md` 的有效结论；只采集或只记录则保留提示，主记忆不改。旧笔记仍能直接误导时，加一个简短的后续更正链接即可，不重写整段历史。
3. 只有本项涉及的主记忆有效结论与入口要点已按范围同步，并回读确认结论及相关链接后，才移除本项待处理提示。只采集、只记录或对应旧结论尚未更新时保留提示；笔记保存完成不触发移除。其他项保持原样，没有待处理项时可移除空标题。

若在步骤之间中断，下次更新先处理相关提示；查阅先按提示判断哪些内容可采用。明确更正可直接按范围使用，待核查保持未知；仅在信息不足时读取相关现有笔记，不要求笔记已创建，也不扫描全库。

新增长期要求默认同步主记忆；明确更正只影响用户指定的范围。重新整理旧材料时，已有明确更正继续有效，除非后来又有新的明确要求替代。

## 指定遗忘

遗忘属于用户明确要求的维护操作。区分删除某条结论与排除整个会话，不扩大范围。

- 先在入口的 `## 整理约束` 留下最小排除说明：已知来源身份或用户指定的主题范围。需要较长说明时链接一篇“遗忘要求”笔记；不复制被要求遗忘的正文。
- 在 `## 待处理` 记录清理范围，再从 notes、主记忆和入口中移除指定内容及误导引用。其他独立材料支持的知识保留，并修正来源。
- 回读确认后移除清理待办，保留最小排除约束。后续 update 在采集前读取该约束，避免旧来源再次生成同一内容。约束未知或身份不清时，不宣称已排除整个来源。
- 不主动生成含被遗忘内容的备份。本库已有副本按用户范围检查；客户端原件及外部备份分别处理，不把本库清理说成全局删除。

## 检查与恢复

用户只问现状时不写文件。入口缺失可定向查看已有内容；修复需按请求写回。旧式配置和对象目录不自动转换。

每轮结果与剩余在对话中交代。需要跨对话保留的具体未完成事项可用入口短提示；无变化不写，mtime 不表示来源已全部处理。精确增量去重不作为这版基本能力的承诺。
