# 已有经验与后续更正的加工示例

以下为虚构材料，展示保留信息价值的方式，不是固定措辞或需要生成的全套文件。

## 选定来源

- Cedar 的主题记忆记载：批量导入返回 `E_REVISION_CHANGED` 时，重新取得当前 revision 并重建本批载荷；直接重复提交旧载荷会再次冲突。只适用于有 revision 校验的接口。正文关联会话甲。
- 会话甲原文确认了上述经验；期间的两次重试只是产生该经验的经过。
- 次日会话乙中，用户补充：清单显示导入完成后先回读目标内容，`--jq` 得到空值本身不能证明写入失败；这次演示省略说明，长期文档仍保留原因。
- 另一个客户端的摘要复述会话甲。它提供另一条查找路径，不增加一份独立执行证据。

## 各对象承载什么

| 对象 | 本例的有用内容 |
|---|---|
| 记录 | 每份选定来源保留身份、必要经过及各自能证明的内容。两天原会话分别记录，导入的跨日文件保留一份并列有依据的事件日 |
| 日总结 | 第一天说明导入冲突的处理方法得到确认；第二天说明补充了写后核实规则。相同会话的原文和摘要在同一天合成一个会话块，链接双方记录 |
| 项目主题 | 结论先行：遇到 `E_REVISION_CHANGED` 重取 revision 后重建载荷；仅适用于对应接口。另保留写后回读规则和“空值不证明失败”的条件，历史重试次数可从记录回查 |
| 项目意识 | 当前已有可复用处理方法；若新接口仍未验证，保留这项未知及下一步。没有当前未决事项时，不为了填满意识复制整段操作步骤 |
| 用户画像 | “本次演示省略说明”保留在任务记录。只有用户明确长期适用的偏好才进入画像，并写明范围 |
| 全局摘要 | 为 Cedar 提供当前状态及项目入口；命令、错误和操作细节留在主题或记录 |

同样的有用结论在不同对象中可以被简短引用，但各自回答不同问题。不要把已有具体经验改成“注意处理导入错误”，也不为缩短正文删掉错误原词、适用范围或未解决问题。

## 更正时

假如后续用户说明“新接口已支持自动刷新 revision，旧接口仍按原方法”，更新涉及的主题及当前意识，保留旧接口条件。将原方法一概写成已撤回，会丢失仍然有效的经验；仅追加新段而不说明适用范围，又会让后来者误用。更正来源可定位、条件可区分、旧待办有去向，才算完成了这次加工。
