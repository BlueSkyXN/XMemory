## XMemory Hook 接入模板（被动采集）

Hook 让宿主在固定时点提醒 Agent 使用 XMemory。插件不安装 Hook，也不带脚本；各客户端支持哪些事件、配置写在哪里、能否让 Hook 直接驱动模型，以该客户端当前文档和实际测试为准。Hook 只负责触发，写不写、写什么仍由技能判断；Hook 退出成功不等于记忆已保存。

## 推荐的三个事件

| 时点 | 做什么 | 交给 |
|---|---|---|
| 会话开始 | 读常驻层：USER.md、当前项目的 AWARENESS.md、MEMORY.md 相关要点；延续任务时加最近两天每日记忆 | xmemory-recall |
| 压缩上下文之前 | 把即将被压缩的阶段性要点写成一份足迹 | xmemory-record |
| 会话结束（或回合结束） | 判断本会话有没有被纠正、说明偏好、做出决定、阶段交接；有就写足迹，没有就不写 | xmemory-record |

可以只接其中一两个。会话开始的读取也可以完全依赖 [读取协议](entry.md)，不接 Hook。

## 给 Agent 的提示文本

宿主支持在事件时向 Agent 注入提示时，使用下面的文本（按事件选一段）：

```text
[会话开始] 如果本次任务延续既有工作，按 XMemory 读取协议读取常驻层；自包含的任务跳过。只读，不写记忆。

[压缩之前] 使用 xmemory-record：如果即将被压缩的内容里有决定、纠正、偏好、阶段结果或未完成事项，写一份足迹；没有就不写。

[会话结束] 使用 xmemory-record：检查本会话是否有被纠正、明确偏好、做出决定或阶段交接；有就按 capture 策略写一份足迹，没有就回复“无需记录”。
```

## 按步数触发

也可以按回合计数触发（每一步、每五步一次）。代价是每次触发都消耗 token，且大部分回合没有可记内容；记录技能会对没有实质内容的回合零写入，但判断本身仍有成本。建议优先按事件触发，按步数只在需要高频留痕的场景使用，并把间隔设大一些。

## 注意

- Hook 能看到的字段以宿主实际提供的为准；没有提供会话记录就不要猜路径。
- Hook 触发的写入仍遵守“只新建足迹”的规则；整理只能由手动或定时任务进行。
- 不要在 Hook 里自动运行整理，避免多处同时整理。
