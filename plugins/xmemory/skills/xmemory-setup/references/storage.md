# 文件格式

本文定义集中记忆库的目录、每类文件的格式、时间与地址写法。它是给 Agent 和人共同阅读的文件约定，不是客户端内部数据库 schema。模板中的占位内容都要替换为实际内容；不适用的可选部分删除；未知写未知。

## 目录

```text
~/.agents/memory/
├── config.toml                          配置：项目、来源、时区、记录策略
├── USER.md                              用户画像（只在库根）
├── AWARENESS.md                         意识
├── MEMORY.md                            主记忆：要点 + 主题索引 + 项目入口
├── topics/<主题>.md                     主题记忆：主记忆的子文件
├── daily/YYYY-MM-DD.md                  每日记忆：当天概要
├── daily/YYYY-MM-DD/HHMM-<短名>-<4位随机>.md   足迹：一个会话或一块来源一份
├── projects/<项目名>/                   项目记忆：AWARENESS.md、MEMORY.md、topics/、daily/
└── state/                               工作状态（调取时不读）
    ├── sources.md                       来源进度
    ├── runs/<日期>-<范围>-<批次>.md     采集清单
    ├── curation/<批次>.md               可续跑整理批次；旧 YYYY-MM.md 保留为历史
    ├── history/<范围>/AWARENESS-YYYY-MM-DD-<批次>.md   意识重写前的副本
    └── withdrawn.md                     撤回标识
```

这是用户主目录中的唯一默认记忆库，不是工作区里的 `.agents/memory/`。库根是 `personal` 范围；`projects/<项目名>/` 是 `project:<项目名>` 范围，结构与库根相同，但没有 `USER.md` 和 `state/`。所有工作状态集中在库根 `state/`，用范围列区分。路径和文件名中的 `<范围>` 写 `personal` 或项目名，不带 `project:` 前缀（冒号在部分系统和同步工具中不可用）。

初始化只创建配置、根入口和明确登记项目的入口。没有内容不创建空目录或空模板。

四层内容与目录的对应：

| 层 | 文件 | 回答什么 |
|---|---|---|
| 常驻层 | `USER.md`、`AWARENESS.md`、`MEMORY.md` | 我是谁；现在该知道什么；有哪些长期结论 |
| 主题与每日层 | `topics/`、`daily/YYYY-MM-DD.md`、`projects/<项目名>/` | 某个主题的稳定知识；某天发生了什么 |
| 足迹层 | `daily/YYYY-MM-DD/*.md` | 那次发生了什么，原件在哪 |
| 原件 | 各客户端原生记忆、会话、工作区文件 | 原话和原始证据（只读，不复制） |

内容类型（偏好、决定、事实、做法、经验、坑）是另一条轴，可以出现在任何一层。

## 名称与时间

- **项目名**：平台项目根目录名，原样保留，例如 `demo-api`、`营销分析`。同名而路径不同的项目写成 `<名>@<父目录名>`。登记后保持稳定。
- **主题名**：小写字母、数字、连字符和点，推荐 `<领域>.<主题>`，例如 `release.tag-companion`。文件名主干等于 `name` 字段，建立后不改。
- **足迹文件**：`daily/<事件日期>/<HHMM>-<短名>-<4位随机>.md`。时间按配置的 `timezone` 换算；跨天会话按各天的事件拆分；短名描述内容；随机串为小写字母和数字。日期已知但时刻未知用 `0000`，并标明只知日期；日期未知用 `daily/undated/0000-<短名>-<随机>.md`，不使用采集当天冒充。新建前确认不存在。
- **每日记忆**：`daily/<工作日期>.md`，日期是事情发生的本地日期，不是记录或整理日期。
- **时间字段**：`event_at` 是事件发生时间（可写起止），`recorded_at` 是写入时间，`valid_from` 是规则开始适用的时间。三者不能互相替代；`event_at` 未知时写未知，不能用记录日期补。
- 精确时间写带时区的 ISO 8601；只知日期可写 `YYYY-MM-DD` 并注明精度，完全未知写 `未知`。给读取工具传时间时显式带时区，不能把一个未注明来源时区的文件名直接当配置时区。
- 相对时间（“昨天”“下周”）写入前换算为绝对日期。

## 配置 `config.toml`

见 [配置模板](../templates/config.toml)。不是任何客户端的原生配置。

- `format = "xmemory/v1"`：文件格式名，与插件版本分别管理。
- `capture`：`"explicit"` 只在用户要求时记录；`"milestone"` 另在被纠正、说明偏好、做出决定和阶段交接时记录。
- `timezone`：IANA 时区名，所有日期按此落位。
- `quiet_minutes`：会话最后活动后多久才视为静默、可以采集，默认 60。
- `[workspace] containers`：工作区容器目录列表；容器本身不是项目，其下第一层目录可作项目根候选。
- `[projects."<项目名>"]`：`roots`（项目根路径列表，可含多台机器）、`repo`（Git 远程地址，可选）、`aliases`（各客户端对该项目的叫法，可选）、`owner`（`xmemory` 或 `external`）、`entry`（`external` 时指向既有入口）。
- `[sources.<id>]`：`client`、`kind`（`native-memory`、`session`、`daily`、`profile`、`workspace`）、`path`、`route`（`by-cwd`、`by-alias`、`by-mention` 或 `fixed:<项目名>`）、`enabled`。会话来源可加 `reader` 说明可用的只读读取方式。

路径使用绝对路径或 `~`。来源只在部分机器上存在是正常的，本机没有就跳过并注明。来源不能指向本库形成自循环。

## 用户画像 `USER.md`

使用 [画像模板](../templates/USER.md)。只放工作相关的身份背景、协作偏好和红线，每条一行并附来源；建议不超过 4 KiB。不收录凭据、证件、与工作无关的个人信息。只在库根。

## 意识 `AWARENESS.md`

使用 [意识模板](../templates/AWARENESS.md)。固定五节，顺序不变：

1. `当前认识`：按工作线分小节；每条写截至时间、结论和核实位置。
2. `近期变化`：带日期的重要变化，链接每日记忆。
3. `冲突与未知`：互相矛盾的说法，双方依据都写。
4. `待处理`：每项一行，稳定行动 key、状态、最近依据、需要谁决定；末尾“搁置”小节放久无进展的项，只写 key、来源日期和原因。
5. `记忆候选`：稳定候选 key、主张、来源、证据缺口或建议与当前状态；后续整理必须处理或保留，不能静默丢失。

条目可标重要度：`[关键]`、`[普通]`（默认，可省略）、`[低]`。建议不超过 16 KiB。只由整理整篇重写；重写前把旧版存入 `state/history/<范围>/`。personal 的意识只写跨项目重点并链接项目意识。

## 主记忆 `MEMORY.md`

使用 [主记忆模板](../templates/MEMORY.md)。主记忆是常驻要点层，不只是链接列表：

- 按分组（偏好与协作、决定、做法与坑、事实与资料位置、项目入口）列出每个主题的一行要点：结论 + 适用条件 + 子文件链接。
- 要点文字等于对应主题文件的 `description`；二者不一致时以主题文件为准，由整理修正要点。
- 库根另列各项目入口；项目内列本项目主题。
- 只列已经存在的文件。建议不超过 200 行。

## 主题记忆 `topics/<主题>.md`

使用 [主题模板](../templates/topic.md)。一个文件一个稳定主张。

| 字段 | 要求 |
|---|---|
| `name` | 必填，等于文件名主干 |
| `description` | 必填，一句话要点，就是 `MEMORY.md` 里那一行 |
| `type` | 必填：偏好、决定、事实、做法、经验、坑（六选一） |
| `scope` | 必填：`personal` 或 `project:<项目名>` |
| `status` | 必填：有效、待确认、已替代、已撤回 |
| `applies_to` | 可选：适用路径、阶段或条件 |
| `sources` | 必填：每项为地址 + 出处类型 + 证据等级 |
| `created`、`updated` | 必填，真实时间与时区 |
| `valid_from` | 何时开始适用；未知写未知 |
| `review` | 可选，到期复查日期 |
| `supersedes` | 可选，被替代的旧主题名 |

正文顺序：主张（保留否定和条件）→ Why → How to apply → 例外 → 演变。经验和坑写清条件、做法、结果和反例。

同主题已有文件时，记录技能新建 `topics/<主题>-<4位随机>.md` 草稿并声明 `supersedes` 或在正文说明，由整理合并。

## 每日记忆 `daily/YYYY-MM-DD.md`

使用 [每日模板](../templates/daily.md)。一个范围每个工作日一份，合并当天所有客户端在该范围的工作：有意义的变化、决定与约束、冲突与未知、长期候选。同一天再次整理时合并旧正文与新增内容、整篇重写并语义去重；不只保留本批内容。末尾“已吸收足迹”保留所有旧项，再逐行加入本批已核对足迹的相对链接、去向和批次 ID。建议不超过 12 KiB，超过时保留必要条件并说明，不硬截断。日期未知的内容用 `daily/undated.md` 单列。

**未整理的足迹**：`daily/<日期>/` 或 `daily/undated/` 中存在，但相应每日记忆的“已吸收足迹”未列出的文件。只有正文提到文件名不算吸收。另须先查同范围的未完成整理批次：登记已写而批次尚未完成时仍须续跑核对。旧 1.2 吸收项没有批次 ID 可保留为旧基线，不能冒称已经过本版核对。晚到历史足迹不按年龄排除。

## 足迹 `daily/YYYY-MM-DD/*.md`

使用 [足迹模板](../templates/record.md)。只新建，不修改；发现错误时新建一份更正足迹并指向原文件。1.2 的足迹没有 `time_basis`、`read_level` 等字段时保持原样，不为补字段改写；整理时按其 `event_at`、`source` 判断时间精度和覆盖范围，不确定的写进每日记忆或意识。

| 字段 | 要求 |
|---|---|
| `name` | 必填，等于文件名主干 |
| `description` | 必填，一句话摘要 |
| `event_at` | 必填，事件起止时间；未知写未知 |
| `time_basis` | 必填，消息/头部/已确认含义的文件名等依据，及只知日期、时区不明等精度边界 |
| `recorded_at` | 必填 |
| `scope` | 必填：`personal` 或 `project:<项目名>`；无法确定写 `待定` |
| `cwd` | 会话类来源必填：会话的工作目录 |
| `client` | 必填：来源客户端，当前对话写当前客户端 |
| `kind` | 必填：`conversation`（当前对话）、`session`、`native-memory`、`workspace` |
| `source` | 必填：规范地址，见下文；当前对话无持久地址时写明 |
| `read_level` | 采集时必填：`full`、`paged`、`partial`、`metadata` |
| `provenance` | 必填：用户原话、AI 汇报、原生转述、执行结果、观察（可多选） |
| `origin` | 可选，已知的原始会话或原始产物地址；不能根据摘要标题编造 |
| `extends` | 可选，本次补充的旧足迹相对路径；不修改旧足迹 |

正文顺序：做了什么 → 用户原话中的偏好和纠正信号 → 决定 → 结果与证据 → 失败与改法 → 未完成 → 去哪找原件。条目可标类型：偏好画像、经历事件、指令约束、工作事实、任务待办、方法做法、产物位置。计划、AI 汇报与已核实结果分开写；不复制完整对话或工具日志。

## 工作状态 `state/`

- `state/sources.md`（[模板](../templates/sources.md)）：每个来源与范围一行：连续完成至的位置、未结清单、最近清单、更新时间。失败、临时跳过和部分读取不能越过；本次成功项在缺口之后时保留产物但不跨越推进。由采集维护，整理不改。
- `state/runs/<日期>-<范围>-<批次>.md`（[模板](../templates/run.md)）：一次采集一份，一行一项：来源 ID、地址/源版本、项目、本地日期、状态、需回补、结果/恢复位置。状态仍为 `已提取`、`无可记内容`、`跳过`、`失败`；四种状态与终结/回补是两条轴。部分提取必须需回补，详见 [采集细则](collection.md)。
- `state/curation/<批次>.md`（[模板](../templates/curation.md)）：一批一份，`run_id`、`scope`、`status`（`pending` / `verified` / `completed`），冻结输入、预期输出、基线、旧待办/候选去向、核对结果和剩余范围。只更新本批记录；未完成文件用于续跑，不是锁。1.2 的 `YYYY-MM.md` 原样保留为历史，不据其中的“未完成”拦截新批次。
- `state/history/<范围>/`：意识重写前的原样副本，文件名含批次 ID。已完成批次的副本最多 10 份、保留 7 天；未完成批次依赖的基线不按年龄删除。只用于恢复和比对，不作为事实来源。
- `state/withdrawn.md`（[模板](../templates/withdrawn.md)）：撤回时才建，每行保存条目 ID、可安全保留的来源地址、撤回日期、执行者和不泄露内容的原因。

## 地址

| 类型 | 写法 | 例 |
|---|---|---|
| 会话 | `<client>:<variant>:<完整会话ID>`，与读取工具的原生写法一致 | `codex:jsonl:<完整ID>` |
| 原生记忆 | `<来源ID>#<相对文件>@heading=<标题>`，整份文件即证据时可省略标题 | `codex-memory#MEMORY.md@heading=<标题>` |
| 库内文件 | 相对路径 | `../topics/release.tag-companion.md` |
| 项目文件 | `project:<项目名>/<相对路径>`，可加 `@heading=` 或 `@<提交号>` | `project:demo-api/docs/plan.md` |
| 云端对象 | `feishu:docx/<token>`、`gh:owner/repo#123`、`hf:spaces/<owner>/<name>` | — |
| 只在某台机器上的 | 绝对路径或 `~/...` | — |

- 会话 ID 和文件路径只从读取结果复制，不截断、不凭记忆手打。
- 会被整体重写的聚合文件用标题锚点，不用裸行号。
- 云端对象只存稳定 ID，不存签名链接或凭据。
- 原件在本机找不到时说明“本机找不到”，不判定原件已删或原结论错误。

## 容量与链接

上限是 XMemory 自己的阅读设计值：画像 4 KiB、意识 16 KiB、主记忆 200 行、每日记忆 12 KiB。超出时按整理规则晋升、移出或拆分，不静默截断，也不删掉条件、来源和未决问题。本库内链接一律用相对路径。
