# 整理细则

整理把足迹和既有记忆加工成当前认识与可复用知识。证据与权限见 [共同约定](contract.md)，格式见 [文件格式](storage.md)。同一主张只维护一份主题；原始记录、当前状态、长期规则各有用途，不按文件数量衡量效果。

## 1. 选择工作与续跑

1. 读当前范围的意识、主记忆、撤回标识和相关每日记忆；列出 `state/curation/` 中该范围的批次。
2. 同范围有确切活跃执行者时停止。批次 `pending`、`verified` 或旧月报里的“未完成范围”都不证明有人正在运行。没有活跃冲突时，先回读未完成批次并续跑，再开新批次；多个旧批次按时间逐一核对，不能覆盖或直接标成功。
3. 工作集合包括：未吸收足迹、未收录主题、替代声明、到期复查、用户当轮要求的更正/忘记、同步冲突、意识中尚未处置的候选。候选按稳定 key、范围、主张与来源识别；同一候选每次整理不得换名新增。
4. 手动整理可以审议旧候选，即使没有新足迹。证据仍不足的保留待确认；不把“用户要求整理”当成“用户确认候选正确”。定时方式仍只生成或维护判断类候选。
5. 只有工作集合为空、没有未完成批次、也没有需修正的正文或索引时，才回答“本次无变化”并零写入。只有暂不可处理的候选时说明原因并保留，内容没变也零写入。
6. 范围过大时按日期或工作线分批。记录本批选择和剩余范围；批次完成与整个回填完成是两个状态。晚到的历史足迹不按年龄排除。

## 2. 从信息到判断

先把材料拆成单条主张，明确对象、内容类型、项目范围、事件/状态时间、实际读到的依据和证据不能证明什么。保留条件、否定、例外和来源分歧；统一名称与绝对日期后再去重。

| 去向 | 判断 |
|---|---|
| 合并已有主题 | 同一主张，补来源、修边界，不新建同义文件 |
| 有效主题 | 满足下一节的证据条件且有长期复用价值 |
| 待确认主题或意识候选 | 有复用价值，但还缺原话、执行证据或明确适用范围 |
| 意识当前认识/待处理 | 当前目标、最新状态、冲突、下一步与需要决定的事 |
| 每日记忆 | 某天有意义的变化、决定和结果；临时状态通常到此为止 |
| 退役/更正/撤回 | 按范围、依据与授权处理旧结论及派生内容 |
| 无需收录 | 重复、无关、琐碎，或敏感内容无法分离；登记原因 |

同一个判断可以在意识中简述、在主题里展开，但证据仍是一条来源链。对已有正式规范或 Skill，主题保存入口、适用条件和有价值的例外，不重写一份规范。

## 3. 何时成为有效主题

先问“这条主张需要什么证据”，再判断证据数量：

- 偏好或决定：亲自读到的用户原话，按原话的范围和生效时间使用。
- 代码行为、测试、部署、文件内容等事实：亲自读到的对应原件或执行结果，只支持它实际覆盖的对象、时间和条件。
- 综合经验或做法：支持同一条主张的两条独立证据，并回读至少一处能支持该主张的原始依据；一次直接验证也可以支持范围足够窄的经验或反例。

客户端、日期或文件不同不自动构成独立证据。一个来源支持 A、另一个支持 B，不能拼成“两条证据支持 A 和 B”。多个客户端复述同一会话，只是一条链。只有原生转述或 AI 汇报、未核到对应原话/原件/结果的，仍是“待确认”，不能按摘要票数转为有效。多主张主题逐条判断，条件不一时拆开。

晋升前回原件核对；原件不可达时保留待确认，不要求为了整理而部署或重跑业务操作。XMemory 的意识、每日记忆、主题和工作状态都不是新的独立证据。AI 的推荐不能写成用户决定；用户接受建议不证明执行结果。

待确认主题的 `description` 包含“待确认”，主记忆保留同样限定；`sources` 和正文写明实际读到的依据及缺口。范围从窄：项目里说的偏好先放项目；明确跨项目要求或在不同项目独立出现且证据充分后，才维护 personal 条目。

## 4. 重写意识与处置候选

有实际变化时整篇重写 `AWARENESS.md`，固定五节沿用 [模板](../templates/AWARENESS.md)。先保存旧版，按工作线综合，避免把新足迹逐条粘贴：

- 当前认识：现在的目标、最新有效结论、为何与此前不同、据此应做什么；注明截至时间和核实位置。
- 近期变化：只放改变判断或下一步的重要变化，链接其事件日期的每日记忆。
- 冲突与未知：写双方主张、证据与缺口；没有裁决依据就保持未定。
- 待处理：每项有稳定行动 key；对旧项逐条给出保留、完成、取消、被替代、搁置或待确认的去向和依据。标“完成”需要执行结果或用户确认；只有 AI 汇报或原生转述时写“待确认”并注明缺少的证据。
- 记忆候选：每项有稳定候选 key、主张、来源、缺口/建议和当前状态；旧候选被接受、拒绝、合并或撤回时在批次里留下去向，不能因本轮没提到而消失。

常规改写幅度为 30%–70%，是自检提示，不是必须凑足的比例。低于 30% 检查是否漏读变化；高于 70% 逐项核对旧待办、冲突和候选。首次生成标“新建”；没有内容变化不为达到比例重写。

容量不足时按低重要度、普通重要度，同级最旧的先移出；稳定内容写主题，完成项写每日记忆，长期阻塞项进入“搁置”。关键项移出需要用户明确同意。逐项记录去向，不静默截断。personal 意识概括跨项目重点并链接项目意识。

## 5. 维护主题与每日记忆

- 主题合并保留 `name`，补来源、条件、反例和更新时间。已生效且证据满足的新主题才能替代同范围旧主题；未来生效、竞争替代或关系循环都保留双方并说明。
- 到期复查给出更新、缩窄、待确认或退役的判断，不能只机械延长日期。
- 主记忆要点等于主题的 `description`，保留状态限定；只链接存在的文件，未收录草稿也纳入本次判断。
- 每日记忆按事件日期重写，**合并旧正文与本批新增事实**；旧决定、条件、重要结果和已吸收列表必须保留或有明确处置。原有已吸收项与本批新项取并集，不只留下“本次”的列表。
- 事件日期未知的材料进入 `daily/undated.md`，不伪装成整理当天。日期后来核实，由手动整理明确更正时间索引并保留原足迹链接。

## 6. 批次状态与写入顺序

每批使用一份 [整理批次模板](../templates/curation.md)，位于 `state/curation/<批次>.md`。范围、冻结输入和输出去向都能回查。状态只有：

| status | 含义 | 下一步 |
|---|---|---|
| pending | 已选择工作；正文未写完或未核对 | 核对已保存内容，补正文并验证 |
| verified | 本批正文已保存并核对；吸收登记尚未完成 | 重新确认正文，再补登记 |
| completed | 正文及吸收登记均已核对 | 本批结束；剩余范围另开批次 |

这些状态是进度，不能用来判断另一个进程是否活跃；没有程序级锁或多文件事务。批次记录不存记忆事实，也不作为调取入口。

按下面顺序执行：

1. 冻结范围、输入足迹与旧候选；新建批次 `pending`。列出预期输出、旧待办/候选与剩余工作。
2. 把现有意识原样保存到 `state/history/<范围>/AWARENESS-<日期>-<批次>.md`；本批重试复用该基线，不用半成品覆盖它。涉及忘记时不复制被撤回原文，先按 [撤回规则](corrections.md) 处理。
3. 写主题、主记忆、画像、意识和每日记忆正文。**每日记忆暂时只保留旧的已吸收列表，不加入本批足迹。** 文件写前、写后都核对当前内容；目标被其他人改变时重读，不拿旧稿覆盖。
4. 回读所有本批输出，完成三项核对：**关键信息保全**（旧待办/冲突/候选的条件、否定、路径、ID、数字和日期）、**已有条目损失**（旧主题、要点、每日正文与旧吸收项）、**日期绝对化**。还要核对来源支持、范围、主题状态与索引一致、链接可回查。失败则修正，无法修正时保留 `pending` 和缺口，停止登记。
5. 正文核对全部通过后才标 `verified`：先把核对结果、输出路径和旧条目去向写入批次并回读。该标记不替代重试时的重新读取。
6. 在各每日记忆累计加入本批已核对足迹的链接、去向和批次 ID；与旧列表取并集。无足迹的复查/候选批次不造空每日记忆。
7. 回读登记，确保每个本批输入均有已保存的去向，且旧登记未丢失；再把批次标 `completed`。剩余日期/候选照实列出，不阻止下一批。整理不更新采集游标。
8. 可清理超过 7 天或超过 10 份的意识历史副本，但必须保留未完成批次所需的基线；按配置完成结束后同步。

## 7. 中断恢复

先按范围查未完成批次，不能因为部分足迹已经列入每日记忆就绕过它。

- 正文写到一半：使用同一批次、足迹路径、主题名与稳定 key 核对，不重复新建已保存结果。
- 正文已核对，登记没写或只写了一部分：重新读正文，补缺失登记，不重复完整条目。
- 登记已写、批次未完成：核对正文和登记后补 `completed`，不能仅凭文件存在宣告成功。
- 回读发现已有吸收标记指向缺失/不合格结果：将该输入恢复为未完成，修复本次错误登记并记录原因；不删除他人的新内容。
- 旧 1.2 月报只作历史资料；有剩余范围就继续，不把“未完成”当锁。旧记录缺少核对依据时明确边界，按相关产物重新核对。
- 无法完成时报告已保存、未核对、未登记和剩余范围；不报告全部完成或本次无变化。
