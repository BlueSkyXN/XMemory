# 更新记忆对象

先读 [共同规则](../xmemory/SKILL.md)，再按用户指定对象阅读 [对象工序](../xmemory/references/objects.md) 的对应部分。只更新选定范围。独立执行时先运行 `status --summary`；由 run 调度时复用本轮报告。

| 对象 | 直接来源 | 输出 |
|---|---|---|
| 日总结 | 当天各类记录及选定的 Skysight 活动摘要 | 全局 `daily/<年>/<日期>.md` |
| 项目总结 | 该项目记录 | `MEMORY.md` 索引和 `topics/` |
| 项目意识 | 该项目近期记录及旧意识中的未决事项 | `AWARENESS.md` |
| 用户画像 | 各记录中的稳定偏好、纠正及导入的画像依据 | `USER.md` |
| 全局摘要 | 已有项目意识、索引及 `USER.md` | `memory_summary.md` |

## 完成一个对象

1. 确认对象本轮应处理的来源范围，读取现有对象及相关记录。完整整理或补全时按范围枚举相关记录，同时检查未链接记录与主题状态，不能只看索引时间。缺少可选的日总结或项目总结，不阻止直接从记录更新意识。
   Skysight 仅用于日总结；按记录更新时保留活动块及并入会话块的 Skysight 线索，按 [Codex 适配](../xmemory/references/sources-codex.md#skysight-活动摘要) 处理。
2. 重写、合并或退役旧内容前复制本次文件作为备份；按照该对象的工序处理新旧证据。日常项目增量不要求通读全部历史主题；完整整理是同一对象的另一个可单独执行的工序。
3. 给结论保留来源链接；原始会话与二手记忆出现同一事实时合并内容并保留双方出处，不把两次转述算作两个独立证据。写冲突或替代关系时，先后只取记录正文的事件时间或 `day`；frontmatter 的 `source_updated`、`updated` 与文件时间只说明版本，不能写成“更晚的更正”。
4. 保存日文件或单个主题前，用当前报告核对该文件全部待更新来源；来源超出本次范围、未处理完或存在阻断检查缺口时，保留原文件并报告待整理。用户明确只要改其中部分条目时同样先不保存：说明保存后其余来源的更正将不再被检查提示，请用户在“一并处理这些来源”和“暂不保存、列为待整理”之间选择。已完成文件使用实际保存时间。项目索引随已完成主题更新，未完成主题与未链接记录继续作为待办。
5. 读回检查正文和链接。独立执行时运行 `status --summary` 并汇报完成与待整理对象；由 run 调度时返回，由 run 统一作最终检查和汇报。

没有新偏好时不凑画像；没有当天内容时不建日总结。判断冲突无法解决时并列来源，写明未知；不以“更晚写入”自动判定哪边正确。

不确定怎样把已有经验与后续更正分配到各对象时，参考 [内容加工示例](../xmemory/references/curation-example.md)，按实际信息取舍，不要求每次生成所有对象。
