# 运行一轮

先读 [共同规则](../xmemory/SKILL.md)，使用 `xmemory/v1.5` 库。`status` 的实际脚本路径和调用方式见共同规则。

## 本轮怎么做

1. 读取配置和用户指定的来源、项目、日期、对象及工作量限制。运行只读 `status`，按 [报告约定](../xmemory/references/status.md) 取得库内现状。首轮无库时使用 [设置技能](../xmemory-setup/SKILL.md)。
2. 需要获取新材料时，按 [制作记录](../xmemory-extract/SKILL.md) 检查选定来源；“库内无过期对象”不表示外部无新材料。用户只要求更新现有记录的派生对象时，可跳过外部读取。
3. 根据新记录、`status` 提示和用户目标，选择要更新的对象，按 [各对象工序](../xmemory/references/objects.md) 执行。日常归入只处理相关增量；完整整理在用户指定或客户端周期任务触发时执行。对象之间没有固定执行顺序，也不要求每轮六类全做。遗忘按 [维护技能](../xmemory-maintain/SKILL.md) 单独完成。
4. 写入结束后再次运行 `status`，读回本轮修改文件。若后写的来源使先写的对象重新过期，继续更新该对象，或明确留到下轮；不能仅因本轮碰过它就说已完成。

## 工作量与中断

- 无额外限制时完成用户指定范围；存在客户端时长或上下文限制时，优先完整完成一个对象，再处理下一个。
- 一个派生对象的应读来源没处理完时，不把半成品覆盖正式对象。部分记录可保存，但必须用真实更新时间并注明 partial；不能改正文却保留旧时间。
- 达到限制、来源不可达或读取失败时，汇报具体来源和范围。下轮从文件身份、时间及缺口重新判断，不依赖本轮报告充当状态库。
- 不为了消除提示而新建空日总结、把无关记录塞进画像，或无依据地把所有时间改成现在。

## 汇报

给出以下事实，数量取自本轮工具结果和实际修改文件，无法确定时写未知：

- **范围**：哪些来源、项目、日期、对象；外部来源是否检查。
- **记录**：新增、更新各几份，未读全或失败的来源及原因。
- **对象**：实际更新的日总结、项目总结、意识、画像和入口路径；整理合并或退役了什么。
- **检查前后**：需要更新或复查的对象数、断链和结构问题数；修复了哪些，剩余哪些。
- **未完成**：未检查的来源、仍过期的对象、没有依据解决的冲突。没有外部扫描时只说库内结果。

不把运行说明写进记忆正文，也不另存一份运行状态文件。
