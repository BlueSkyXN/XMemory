# 调取方法

自包含的问题（当前时间、翻译、改一句话、一行命令、与历史无关的改动）不查记忆。下面这些情况值得查：

- 问题提到的项目、目录、模块出现在 `memory_summary.md` 里；
- 用户提到“上次”“之前”“沿用那个决定”，或要求保持一致；
- 任务有歧义，可能取决于此前的选择；
- 要继续既有工作、确认当前状态、回看某段时间。

拿不准时做一次快速查阅。

## 快速查阅（一般 4–6 步）

1. 读记忆根下的 `memory_summary.md`，提取与问题相关的项目和关键词。
2. 读 `projects/<项目>/AWARENESS.md`：当前认识、冲突、待处理。
3. 用关键词 `rg -n` 搜 `projects/<项目>/MEMORY.md` 和 `projects/<项目>/topics/`，只读命中的任务组或条目。
4. 需要细节时，读命中条目链接的 `sessions/…` 会话摘要；按日期找事情时看 `projects/<项目>/timeline/<年-月>.md`。
5. 还需要原话或原始证据时，用会话摘要里的 `session_ref` 运行 `session <session_ref>` 读原会话（只读，可分页）。
6. 没有命中就停止查阅，正常完成任务。

执行中如果反复报错、遇到意外行为，或怀疑以前处理过，再查一次。

## 要不要现场核实

- 会漂移、核实又便宜的事实（分支、版本、部署状态、文件内容），先核实再用。
- 会漂移但核实代价大的，可以先按记忆回答，同时说明来自记忆、可能过时，并主动提出现场核实。
- 不太会变、核实代价大的，可以直接按记忆回答。
- 没有在本轮核实过的记忆，不要说成“已确认的当前状态”。

## 回答时

- 说明结论来自 XMemory，并给出处：记忆根下的相对路径，或原会话的 `session_ref`。
- 主题 `status` 为待确认、已替代、已撤回的内容，不能去掉限定当作当前事实。
- 记忆与当前文件或用户说法冲突时，以当前证据为准，并指出差异。
- 没找到时说“在本次查阅范围内没有找到”，不说“从未讨论过”。
