# 来源选择

## 先按问题选材料

| 问题 | 优先材料 | 何时展开 |
|---|---|---|
| 继续工作 | 近况、未处理的事件文件、工作区现状 | 交接缺信息时 |
| 为什么这样决定 | 决定条目、原始用户要求或决定文档 | 需要理由或确认原文时 |
| 最近有什么变化 | 当日文件、事件文件、变化过的原生记忆、相关产物 | 摘要不够或相互矛盾时 |
| 哪些经验可以复用 | 经验、反例、正式 Skill/规范 | 当前条件是否匹配不明时 |
| 是否真的完成 | 测试、交付、运行或验收结果 | 动态事实要实际核实 |

无需每次按客户端逐个扫描。已有摘要足够就不重抽全文；摘要无法支撑的部分保持待确认。

## 各类来源边界

- **原生记忆**：只读用户登记的入口和相关主题，不假定不同产品目录格式相同。它们经常被整体重写，引用时用标题锚点。
- **已有摘要类产物**：各客户端整理过的记忆、已有的日报或周报、项目交付记录，优先于原始会话读取；它们是转述，必要时回到它们指向的原件。
- **历史会话**：用当前宿主真实提供的只读查询或可靠导出。没有读取工具就说明限制，不编造命令；不解析未知数据库或拿其他客户端路径冒充；仍在写入的会话先跳过。
- **工作区文件**：读取点名文件或与本次问题相关的有界候选。文件新增、修改时间和 Git diff 都是查找线索，不直接证明业务完成。
- **执行结果**：按需读取确认结果的片段，保留可回查的任务或文件地址，不复制整套工具日志。

不同产品的实现借鉴见 [设计来源](../docs/design-sources.md)。那份文档解释方法来源，不是本机来源清单，也不授权读取任何个人数据。

## 地址与“找不到”

地址分库内文件、项目文件 `project:<ID>/<相对路径>`、云端对象和只在某台机器上的路径四类，写法见 [文件格式](storage.md) 的“地址”一节。

原件在本机找不到时，说明“本机找不到这个原件（可能在别的机器上、存储没挂载或已移动）”，用记忆中的摘要回答并注明截至时间。不猜它在哪台机器，也不因此认定原结论错误。仅靠找不到的原件支撑、又会影响行动的结论，标为待确认。采集时本机不存在的来源跳过并在事件中注明。

## 本地与云端各有一份的文档

事件或记忆头部用 `artifacts` 列出各载体，`primary` 写以哪份为准，`synced` 写最近一次确认两边一致的时间和版本。

- 读：先读主本；主本读不到（离线、没登录、不在本机）就读副本，并说明副本截至同步点、可能落后。
- 比对：两边都能读、结论又依赖细节时，看主本在同步点之后是否改过；改过就以主本为准，并说明两边已不一致。采集时新建一条事件记下差异，由整理写进近况；调取只在回答中说明。
- 写：每次写回云端或用云端覆盖本地，都新建一条事件，带上新的同步点；主本更换也新建一条。
- 长期引用的文档单独建一条记忆，写明各载体、主本和最近同步点，其他地方引用这条。

两份是否一致是会变的事实，依赖它行动前要核实。

## 来源表达

例如：

```text
S1：用户决定；当前对话，未提供持久地址。
限定：候选阶段只在测试环境验证。
S2：测试结果；project:demo/reports/test-result.md@heading=配置测试。
观察：实际读取时间；它不能证明已经部署。
```

这是格式示例，不是发生过的测试。记录真实时间，未知就写未知。原始来源无法访问时，注明当前能看到的是哪份转述；不因重复转述提升可信程度。

来源后来消失或改名，意味着需要重新定位或标记无法回查，不自动证明原结论错误。
