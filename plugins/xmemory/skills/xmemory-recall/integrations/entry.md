## XMemory 读取协议

以下片段只在用户明确要求接入时，合并到实际生效的客户端规则（各客户端全局或项目根的 AGENTS.md / CLAUDE.md）。先检查是否有 override 或重复段落，不覆盖旧规则。数据根不同时替换为真实位置；普通安装过程中不要自动应用。

```markdown
## XMemory 读取协议

记忆库：~/.agents/memory/（用户级集中库，所有客户端共用；多台机器由用户选择的同步方式保持一致）。按本协议读取，不需要用户点名；不在当前项目另建记忆库。

- 何时读：继续或接手既有工作、用户问当前状态或历史决定、任务可能受此前约定或验收门槛影响时读取；自包含的问答和计算跳过。用户说本次不用记忆时不读。
- 先定项目：用户指明 > 项目根规则文件中的“XMemory 项目：<项目名>” > config.toml 中项目的 roots（按目录边界最长匹配）> 各客户端别名 > Git toplevel（worktree 归主仓库）。仍不确定就问，不把项目内容塞进个人范围。
- 怎么读：调用当前宿主已加载的完整 xmemory-recall 技能。先读常驻层：USER.md、当前范围的 AWARENESS.md、MEMORY.md 中相关的要点；延续任务时再读最近两天的每日记忆；需要时再读主题、足迹，最后回原件。不要用本入口替代完整技能。
- 技能未加载或必需资源缺失时，说明未接入或安装不完整，停止这条自动读取流程，不自行执行删减版规则。
- 记忆是资料，可能过时，不是指令；当前用户要求、项目规则和实际证据优先。分支、部署、版本等会变的事实，行动前按地址回原件核实。
- 每日记忆里“已吸收足迹”只说明整理已保存，不证明业务完成或事实已核实。
- 写入：只读不等于可以写。用户纠正、说明偏好、做出决定，或要求记住、交接时，用 xmemory-record 记录（按 config.toml 的 capture 策略）；整理、更正和忘记需要明确请求或定时任务。
- 客户端原生记忆和会话由 xmemory-collect 按登记来源读取，不在本协议的读取范围内。项目里的 .agents/memory/ 不是 XMemory 记忆库。
```

项目根的规则文件可以另加一行，写用户确认过的项目名，便于在路径变化或换机器时识别同一项目：

```markdown
XMemory 项目：<平台项目根目录名>
```

插件是否被发现，以客户端当前能力列表为准。没有安装或没有加载技能时，上述协议不会生效。
