# XMemory 采集

从原生记忆优先取线索，必要时回原始会话补证据。先读 [共同约定](./references/contract.md)、[采集细则](./references/collection.md)、[客户端映射](./references/clients.md)；写入格式见 [文件格式](./references/storage.md)。

## 1. 定范围

只读登记且启用的相关来源，或用户当轮点名的资料。明确项目、时间窗、时区；没有时间窗先续未结清单，再从连续完成位置接着采；无基线只采点名材料。

只要求检查或“看看”时只读，不写清单。会话来源使用宿主历史查询、已安装读取技能或可靠导出；不解析未知数据库。仍活跃的会话先跳过并保留回补。

## 2. 清单与提取

1. 用不过滤的方式列出本次来源项（读不到的链接和条目也列入），按细则的游标顺序写 [清单](./templates/run.md)，核对条数和分页/扫描截断。
2. **写前读取 `state/withdrawn.md` 与相关已有足迹**，匹配原件地址和已知来源链。撤回项终止收录，重复项链接旧足迹；不靠随机文件名避免重复。
3. 原生聚合文件按变化条目提取，会话按事件日分段；保留读取深度、原始会话线索和未读边界。摘要与原件同源，但补读得到新证据时可建补充足迹并写 `extends`。
4. 按 [足迹模板](./templates/record.md) 新建。项目归属不明写待定；日期未知用 undated，时刻未知用 0000 并注明精度。来源地址从实际结果复制；原生引述不标为亲自读到的用户原话。
5. 每项填写状态（已提取/无可记内容/跳过/失败）、需回补和结果/恢复位置；部分提取也需回补。没有实质内容不建足迹。
6. 回读清单和产物：各状态合计正确、空状态为 0、回补项明确；至多抽查 3 份足迹的原件、日期与范围。
7. 仅推进**连续完成前缀**，顺序让新条目排在后面（会话按最后更新时间从旧到新）；失败、活跃、部分读取和临时不可访问均不能跨越。将未结清单保留在 [来源进度](./templates/sources.md)，下次先回补；后面的成功产物保留并去重。

## 3. 重试与交付

重试复用未结清单，只补未完成内容。来源内容变更或读到更强原始依据时保存补充足迹，不覆盖旧文件。写失败就不推进对应项；回补尚未完成不报告全覆盖。

只改本批清单和本来源/范围的进度行；每个来源进度仅由一处维护。可并行采不同独立来源，但不能因批次名不同就同时覆盖 sources 全表。

用户同时要求整理时，核对采集结果后调用整理。报告清单、产物、各状态数、需回补数与读取边界，分别说明处理结束和覆盖完整。
