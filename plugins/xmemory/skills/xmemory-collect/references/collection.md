# 采集细则

把实际读到的材料变成有来源、范围和事件时间的足迹。来源映射见 [客户端读取映射](clients.md)，格式见 [文件格式](storage.md)。先看原生记忆，再按需要补原始会话和执行结果。

## 1. 冻结范围与清单

1. 明确来源、项目、时间窗和时区。未给时间窗时，先读 `state/sources.md` 的未结清单，再从连续完成位置接着采；没有可靠进度时只采点名材料，不自行全量回填。
2. 从目录/会话列表逐项建立 `state/runs/<批次>.md`（[模板](../templates/run.md)），保留真实列表顺序及排序依据、来源地址和可获得的版本（内容摘要或更新时间）。核对行数，检查扫描/分页是否截断。未取尽就继续分页、缩小范围或明确留下缺口，不能推进到窗口末尾。
3. 写前读取 `state/withdrawn.md` 和目标范围已有足迹，按来源地址、已知原始会话与范围匹配；已撤回的不重新收录，同源同版本且无新信息的不重复建文件。
4. 每个来源同时只有一个进度维护者。若要分批并行，按不同来源或不重叠且独立登记的范围划分；不同清单文件名本身不能避免共享 `state/sources.md` 的冲突。写前重读，只改自己的行。

## 2. 逐项提取

| 来源 | 提取单元 |
|---|---|
| 会话 | 按会话和事件日期分段；跨天按消息时间拆，不把所有内容归到会话开始日 |
| 原生摘要/主题 | 一个摘要文件，或聚合文件中一个有变化的条目块；来源角色见读取映射 |
| 工作区 | 一次有意义的变化，只读相关文件；修改时间仅作线索 |

同一个会话的多客户端转述要保留共同来源链，不重复创造“独立证据”。首次采摘要后再读到原始用户话或执行结果，可以创建**补充足迹**，以 `extends` 指向旧足迹，说明新增内容和覆盖范围；同一会话已有摘要不等于其原件已完整读取。

每项先判范围、事件时间和证据类型：

- 范围按配置 roots/aliases、实际 cwd 和共同约定定位；不确定写 `scope: 待定`，落在库根，交给整理；不把它当 personal 偏好。
- 带时区的消息/事件字段优先；日期字段和文件名含义已知时才能用。更新时间、采集时间不等于事件时间。已知日期、未知时刻时文件名用 `0000` 并写明“只知日期”；事件日期未知写 `daily/undated/0000-<短名>-<随机>.md`，`event_at: 未知`。不为满足日期目录编时间。
- 读到用户原话才标用户原话，读到原始输出才标执行结果；摘要转述的引号仍是原生转述。
- 对分页/截断写清已读范围、下一页或恢复位置与未读部分。`read_level: partial` 不等于全文覆盖；列表元数据只能用于定位，不能生成声称读过正文的足迹。

足迹按 [模板](../templates/record.md) 写成“目标与变化、偏好/纠正信号、决定、结果与边界、教训、下一步、原件位置”。保留必要的条件、反例、版本和行动 key；不复制原文或按每条消息制造文件。无实质内容不建足迹。

## 3. 状态、回补与连续进度

清单状态仍是 `已提取`、`无可记内容`、`跳过`、`失败`；另有“需回补”列，不能把填了状态等同处理完成。

| 情况 | 状态与回补 | 能否越过这项推进 |
|---|---|---|
| 已完整提取，产物回读可用 | 已提取；否 | 可以 |
| 全文确认无价值/同源重复 | 无可记内容；否；重复时链接已有足迹 | 可以 |
| 已撤回、明确不在范围、无法安全分离的敏感材料 | 跳过；否；写清终止原因 | 可以，范围/源版本不变时 |
| 仍活跃、临时不可访问、部分读取/分页未取尽 | 跳过或已提取；是；写下一次恢复位置 | 不可以 |
| 读取或写入失败 | 失败；是 | 不可以 |

核对清单所有行均有状态、回补标识与结果，各状态合计等于总行数；检查足迹回查地址及事件日期，至多抽查 3 份，不足 3 份全部检查。存在未取尽列表时报告覆盖缺口。

`state/sources.md` 只推进到**从旧位置起连续完成的前缀**。例如 A 成功、B 活跃、C 成功，进度最多到 A；C 的产物保留，下次按来源/版本去重。将本批含回补项的清单加入“未结清单”，不能被最新一张清单覆盖。下次先重试未结项；无法回补时保留，不阻止处理其他项，但游标仍不能越过缺口。全部项终结后关闭该清单的回补状态。

旧 1.2 进度若只有时间/最后 ID，没有足够清单支持，不当作完整覆盖证明；按用户给定范围重叠读取并去重。无新的处理结果时不改进度时间或新建空清单。采集失败后从原清单续跑，避免同源内容因新批次名而重复写入。

## 4. 首次回填与回报

先设置和确认项目/来源，再逐客户端采原生记忆，按“项目 × 月份”补会话。原生摘要覆盖不足、需要确认关键决定、跨天日期不清时回原件；只有正文覆盖充分且无新证据需求，才跳过已覆盖会话。若干批后整理一次。

报告清单路径、总项数、各状态数、需回补数、列表截断、读取深度和实际产物；分别说明本批处理结束、来源覆盖完整、记忆已核实。三者不等价。最终对活跃项目用“上次到哪、决定为何、坑如何避”三个问题做只读调取验收。
