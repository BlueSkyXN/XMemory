# 采集细则

采集把原件变成足迹，相当于 Codex 的第一阶段逐会话提取，但覆盖所有客户端。读什么、怎么读见 [客户端读取映射](clients.md)；足迹和清单格式见 [文件格式](storage.md)。

## 1. 先定范围，写清单

1. 明确本次的来源、项目和时间段（带时区）。用户没给时间段时，从 `state/sources.md` 的进度接着采；没有进度就只采点名材料，不静默扫描全部历史。
2. 新建本批清单 `state/runs/<日期>-<范围>-<批次>.md`（[清单模板](../templates/run.md)）。从列目录结果或读取工具的列表输出**逐项抄录**，一行一项，不凭印象，不只抄一部分。
3. 清单写完，先核对两件事：
   - 行数等于列表输出的条数；
   - 列表本身是否被上限截断（例如读取工具的扫描上限、分页未取尽）。截断就继续分页或缩小范围，直到取尽；做不到就把截断情况写进清单开头。
4. 每批只改自己的清单。多个采集同时进行时，各自用不同的批次名。

## 2. 提取单元

| 单元 | 一份足迹 |
|---|---|
| 会话 | 一个会话一份；跨天的长会话按天各一份 |
| 原生记忆 | 一个原生摘要文件，或聚合文件中一个变化的条目块，一份 |
| 工作区变化 | 一个有意义的变化（一次合并、一批相关改动）一份 |

不跨会话、跨周按主题合并，否则时间线会丢失。同一个会话在多个客户端都有摘要时（例如 Codex 摘要与原始会话），只建一份足迹，`source` 写最直接的那个，其他写进正文的“去哪找原件”。

## 3. 写足迹

- **位置**：`daily/<事件日期>/<HHMM>-<短名>-<4位随机>.md`，日期和时刻取事件开始时间，按配置时区换算；文件名或目录名中的时间可能是 UTC，按 [客户端读取映射](clients.md) 判断后再换算。范围是项目时写在 `projects/<项目名>/daily/` 下。
- **头部**：按 [足迹模板](../templates/record.md) 填写；`source` 从读取结果复制完整地址；`read_level` 如实写读到什么深度。
- **正文**：总结与索引，不复制原文。重点写：
  - 用户原话里的偏好和纠正信号（写成“用户说……→ 以后……”）；
  - 决定及理由；
  - 结果与证据（区分计划、AI 汇报和已核实结果）；
  - 失败与改法；
  - 未完成事项；
  - 去哪里找原件。
- **没有可记内容**（问候、空会话、琐碎查询、与已有足迹完全重复）：不建足迹，在清单里把该行标为“无可记内容”。
- **不确定归属**：`scope` 写 `待定`，放在库根 `daily/` 下，整理时处理。

## 4. 标记状态与推进进度

每读完一项，就在清单中把该行状态改为：

- `已提取`：附足迹相对链接；
- `无可记内容`；
- `跳过`：附原因，例如仍在写入、超出范围、敏感无法分离；
- `失败`：附原因，例如读取报错、原件不可访问。

全部完成后核对：
- 状态为空的行数为 0；
- 各状态行数之和等于总行数；
- 抽查至多 3 份足迹（不足 3 份时全部抽查），按 `source` 能打开原件，并核对文件名日期与 `event_at` 一致。

核对通过后，才把 `state/sources.md` 中对应来源的进度推进到最后一个已完成的项；`失败` 行之后的部分不推进。

## 5. 首次回填

首次把历史记忆导入时，量大，按下面的顺序分批执行：

1. 先跑设置：发现并登记项目（含各客户端别名），确认时区。
2. 原生记忆优先：逐个客户端读原生记忆，每个客户端一批清单。
3. 会话补缺口：按“项目 × 月份”分批，只处理原生记忆没有覆盖、或用户点名的会话。
4. 每完成若干批就整理一次，避免足迹积压。
5. 全部完成后，对每个活跃项目准备三个真实问题（上次进行到哪、某个决定为什么、某个坑怎么避），用调取技能验证能否答出、能否给出日期和来源。

批次可以由多个会话或 Agent 分头执行：采集只新建足迹、各改各的清单，所以互不覆盖；整理仍然只能一处进行。

## 6. 回报

说明：新建了哪些足迹，清单路径，以及核对结果（总行数、各状态行数、空状态行数）。来源不在本机、读取被截断、只读了部分，都要说明。“在本次范围未发现变化”不等于“所有历史都已覆盖”。
