# 研究 demo 与已有资料

## 版本关系

XMemory 1.0.0 是首个正式插件版本，`config.toml` 使用格式名 `xmemory/v1`。研究 demo 只用于验证想法，不属于正式发布历史。1.1.0 和 1.2.0 都在 `xmemory/v1` 名下重新定义了布局；1.2.0 改用 `USER.md`、`AWARENESS.md`、`MEMORY.md`、`topics/`、`daily/`、`state/` 的结构。

安装插件不读取或改变研究 demo、Office Memory、客户端原生记忆或已有记忆库。发现目标目录已有未知内容时先确认归属；文件名或格式字符串相同，不能自动视为正式 XMemory 记忆库。项目里的 `.agents/memory/` 与用户级的 `~/.agents/memory/` 只是名字相同。

## 按 1.1.x 布局建立的库

1.1.x 布局（`CURRENT.md`、`notes/`、`records/YYYY-MM/` 等）不做自动转换。原因是旧布局把事件按记录时间存放，项目归属也可能不完整，无法可靠拆回真实日期和项目。处理方式：

1. 用户另行授权后，把旧库整体移到一个归档目录（例如 `~/.agents/memory.archive-<日期>/`），不删除。
2. 按本版初始化新库，按首次回填流程从各客户端重新采集。
3. 需要时把归档库当作只读来源读取，内容按原生转述处理，不当作已核实事实。

## Office Memory 迁移

Office Memory 的方向是迁入集中库并停用旧流程，不是永久维护两套。迁移在用户另行明确请求时进行，旧流程在迁移期间照常维护：

1. 核对来源、目标项目名和引用。目标项目名等于该项目根目录名。
2. 长期条目逐条转为 `projects/<项目名>/topics/` 下的主题，原 key 作为 `name`，类型按 fact→事实、preference→偏好、decision→决定、runbook→做法、lesson→经验映射，保留复查日期和来源；同时生成 `MEMORY.md` 要点。不合并、不删减条目。
3. 当前认知（AWARENESS）转为项目 `AWARENESS.md`，五节结构相同；轮转副本迁入 `state/history/<项目名>/`。
4. 历史日期记录逐份转为同日期的 `daily/<日期>.md`，内容保留；原文件留在原处作为只读来源。
5. 来源配置中的各客户端来源，转为 `config.toml` 的 `[sources]`。
6. 切换读取入口：项目规则文件中的读取说明改指 XMemory。验证当前事项、长期结论和历史日期都能找到后，再停用旧写入流程。

没有完成这些步骤，就不能只改 owner 宣称迁移成功，也不自动删除历史资料。迁移前，Office Memory 可以登记为 `owner = "external"`，只读其入口。

## 明确需要复用研究资料时

当作一次有范围的资料接入，而不是版本升级：用户选定资料和目标项目 → 设置技能登记只读来源 → 采集技能读取必要内容写成足迹 → 整理技能判断哪些进入意识或主题。不复制整套研究目录，不假定研究结论已经验证；原件保留，接入完成不授权删除研究材料。研究 demo 自身的说明、模板和虚构测试不是用户事实，不写入正式记忆。

## 多客户端与多设备

共享一套数据需要各客户端都能访问同一个根。多台机器时同步整个库，同步方式（同步盘、私有 Git 仓库等）由用户选择；跨设备复制、云盘冲突和权限由用户现有系统处理，不属于插件功能。记忆内容不带设备特征，各台机器只采集自己能读到的来源；同一时间只在一处整理。
