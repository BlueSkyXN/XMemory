# 最小闭环（虚构示例）

下面的 `demo`、路径和事件都是教学数据，不代表用户真实项目。试用时使用独立的空测试目录；不要指向唯一正式资料。

## 设置

输入：

> 使用 XMemory 设置，在我指定的空测试目录初始化记忆库。项目 ID 为 demo，工作区使用我给出的测试路径。不读个人来源，不改客户端规则。

预期：只创建配置、根入口与 demo 项目入口；没有近况、事件文件、当日文件或空主题目录，没有自动任务。

## 记录

输入：

> 使用 XMemory 记录，给 demo 留交接：配置解析代码已修改，本轮单元测试通过；尚未部署。下一步在测试环境部署验证。这是测试案例，不是真实生产状态。

预期新建一个事件文件，例如 `projects/demo/records/2026-10/2026-10-06T1530-config-handoff-a1b2.md`：

```markdown
---
identifier: 2026-10-06T1530-config-handoff-a1b2
recorded_at: 实际记录时间与时区
event_at: 未知（示例未提供实际时间）
line: config
provenance: [用户指示, 助手]
evidence: [当前对话，未提供持久地址]
---
# 配置修改后的交接

## 目标与变化
配置解析代码已修改。

## 已确认与待确认
当前输入报告单元测试通过；本次记忆操作没有重新运行测试。
尚未部署，不能认定线上问题已解决。

## 未完成与下一步
在测试环境部署验证。
```

这段正文只说明措辞；执行时填真实记录时间和随机串，不能复制示例时间冒充事件时间。记录只新建这一个文件，不改入口、近况或当日文件，也不自动生成长期经验。

## 整理

输入：

> 使用 XMemory 整理 demo。旧行动项“确认回滚步骤”仍未完成，不要因为新交接没提就删掉。

预期：

- 近况保留 `verify-deployment` 与 `confirm-rollback` 两项，区分“代码已改”和“未部署”；
- 先保存近况和必要入口变更并回读确认，最后在今天的当日文件追加一节：“处理的事件”列出上面的交接及已保存的去向，“状态变化”写明新增 `verify-deployment`、`confirm-rollback` 继续保留；
- 不新增个人规则，不把“测试案例”写成生产事实。

## 调取

输入：

> 使用 XMemory 调取，继续 demo。能不能认为部署已完成？只读。

预期：不能。截至所读的近况和事件，只确认到报告的代码修改和单元测试，部署未验证。指出来源和下一步，不写任何文件。另一客户端或另一台机器使用同步后的同一个库，应得到相同材料，但这一效果仍需实际安装后验证。

## 纠正与替代

输入：

> 记住：以后汇报时把实现、测试、部署和验收分开写。

预期：用户明确要求，记录新建一条记忆。若已有同主题记忆，就新建带随机串的文件，并在 `links` 中声明替代旧条目；旧文件由下一次整理标为“已替代”，入口也由整理更新。记录本身不修改任何已有文件。

定时整理先核对替代对象、范围、冲突和生效时间，只更新状态、必要元信息和入口，不合并正文。若需要合并，保存带原记忆地址的待确认建议；下次整理仍须保留未处理建议。

## 晚到与中断重试

以下是供宿主实际执行的验收步骤，不表示本示例已经通过行为测试：

1. 在测试根放入一条 45 天前记录、从未登记处理的虚构事件。整理应通过事件清单与所有当日处理登记的差集发现它；不能因超过 30 天而忽略。只在“决定与冲突”中提到它，也不算已处理。
2. 在宿主测试工具层让 `CURRENT.md` 的写入失败。整理应停止 demo 的后续写入，不把该事件登记为已处理，报告已成功与未完成部分。
3. 解除故障后重试，应核对现有结果并只补缺失步骤。再让当日文件写入失败：近况和入口已成功时先保留；下次重试核对后补登记，不重复创建记忆、待办或建议。
4. 所有相关结果和登记一致后再执行一次，没有变化时文件内容保持不变。任何剩余事件、未读来源或失败都须说明，不能以“本次无变化”代替。

故障只注入隔离测试根；新会话测试需保留输入、实际文件变化及失败位置，不能用手工写出预期文件来替代 Agent 执行证据。
