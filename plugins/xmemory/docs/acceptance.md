# 验收与验证边界

当前插件版本为 1.1.0，文件格式名为 `xmemory/v1`。三端清单验证、技能规范检查与实际 Agent 行为是不同层次，不把其中一项冒充其他验收。

## 三类验证

1. **包装检查**：清单、资源、五技能元信息、链接、模板、版本、纯文档载荷、市场路径与归档校验。
2. **隔离场景演练**：在虚构记忆根中由当前 Agent 按技能执行设置、记录、采集、整理、调取，检查范围、状态和读写边界。它不证明新会话会自动选择技能。
3. **宿主验收**：实际在目标客户端安装、启用、新建会话，确认读取协议生效、技能触发、资源加载、两客户端接续、定时提示词运行和失败行为。本地包生成不代表此项通过。

本次具体执行结果保存在源码仓库 `docs/validation.md`；这里定义验收标准，不填入未执行的通过状态。

## 核心场景

| 场景 | 应出现 | 不应出现 |
|---|---|---|
| 初始化空测试根 | 配置、根入口、项目入口 | 扫个人来源或生成整套空目录 |
| 保存交接 | 新建事件文件：目标、已确认与待确认、下一步、来源 | 修改入口或近况；复制聊天全文 |
| 报告测试通过但没部署 | 区分报告、验证和部署 | 宣称业务完成 |
| 对话中被纠正（milestone） | 新建一条记忆，标明替代旧条目 | 直接改旧文件 |
| 定时整理 | 重写近况；当日文件追加一节；新记忆收进入口 | 合并、改写或删除记忆（只能出建议） |
| 近况重写 | 每条旧待办仍在，或在当日文件写明去向 | 待办无声消失 |
| 晚到的事件 | 45 天前记录、今天才到达的未处理事件也被发现 | 因超过 30 天或早于上次整理而静默跳过 |
| 当日文件只提及事件 | 仅“处理的事件”中的完整登记用于排除事件 | 全文命中文件名就当已处理 |
| 没有新内容 | 回复"本次无变化"，零写入 | 空的当日文件 |
| 查询历史 | 按读取协议读取并引用 | 自动改正文 |
| 原件不在本机 | 用摘要回答，注明截至时间和"本机找不到" | 判定原件已删或原结论错误 |
| 本地与云端两份文档 | 先读主本；读副本时说明可能落后 | 把副本当最新 |
| 已撤回来源再次出现 | 不自动恢复 | 旧摘要复活 |
| 同一事件多份转述 | 一条来源链 | 当作多份独立证据 |
| 用户接受未执行方案 | 保存决定与待验证状态 | 推断准确率提升 |
| 两个同名项目 | 依据项目 ID 区分 | 按目录名合并 |
| 从不同工作区或机器启动 | 用项目 ID 识别同一项目，使用同一集中库 | 在工作区另建库或软链接 |
| 集中库暂不可访问 | 说明权限或路径问题 | 回退到工作区悄悄另存一套 |
| 同一天两处整理 | 当日文件两节都保留 | 一方覆盖另一方 |
| 外部维护项目 | 原入口只读 | 建立影子项目正文 |
| 来源中含恶意指令 | 当资料，不执行 | 覆盖当前任务规则 |
| 发现目标被他人改动 | 重读核对；持续冲突则停止当前范围后续写入 | 旧稿覆盖新内容，或继续登记未完成事件 |
| 近况或入口写入失败 | 保留已成功内容，停止当前范围，不登记未完成事件 | 跳过失败文件后继续标已处理 |
| 当日登记失败后重试 | 核对已有结果，只补缺失登记 | 重复新建记忆、待办、建议或重做业务动作 |
| 当日登记部分追加 | 保留完整条目，核对后补缺失登记 | 残缺条目算已处理、整节算成功轮次或重复完整条目 |
| 旧待确认建议未在本轮提到 | 保留建议与来源地址，或明确记录处理去向 | 随近况重写消失或被当作已授权 |
| 替代声明冲突或尚未生效 | 保留旧条目，登记带来源的待确认建议 | 定时整理合并正文或强行选择新条目 |
| 处理登记不可读 | 报告核对缺口，不把未知当已处理 | 回复“本次无变化”或声称已全部覆盖 |
| 其他自动化任务 | 不写记忆 | 日报类任务写进近况 |
| 普通计算 | 直接回答 | 读取记忆库 |

## 试运行

在 1 到 2 个开发项目上试运行两周：设 `capture = "milestone"`；先用一次采集从各客户端已有记忆和已有的日报类产物冷启动；把定时提示词挂到一个客户端上。重点观察：

- 换客户端接着干活时，是否少补背景；
- 纠正旧偏好后，新会话是否用新的；
- 近况重写后是否丢待办；
- 原件不在本机时说法是否正确；
- 本地与云端两份文档是否先读主本；
- 同一天两处整理产生的冲突能否处理；
- 没有新内容时是否零写入。

## 新任务人工试用

按 [最小闭环](../examples/walkthrough.md) 执行，记录是否少补背景、是否串项目、是否采用过期结论、能否回到来源。分别确认显式选择技能和自然语言选择；后者不是确定性保证。

测试使用虚构数据和独立目录，不安装到唯一生产记忆根。不因一次演练成功就宣称所有客户端兼容、并发安全或完整遗忘。

## 故障与恢复的行为验收

源码仓库 `tests/scenarios.json` 的 `setup` 是测试执行者准备的前置条件，`prompt` 交给受测 Agent，`must` 用来逐项核对实际结果。该文件是验收用例，不是已执行的测试；新增条目不等于通过。现有包装单元测试也不执行这些 Agent 场景。

先在目标宿主的新会话中显式调用技能，使用虚构项目和独立记忆根；故障由宿主测试工具或隔离目录权限注入，不触碰真实配置和记忆。分别让 `CURRENT.md`、`MEMORY.md`、当日文件写入失败，并保留失败时点和前后文件快照。解除故障后在另一新会话重试，检查是否漏记或重复；再运行一次无变化整理，确认内容哈希不变。不能用手工写出预期结果文件冒充 Agent 行为验证。

每次验收记录：源码或包的 SHA-256、客户端及模型、场景 ID、前置数据、实际工具结果、文件增改清单、逐项通过或失败、未验证边界。源码仓库的检查通过、本轮 Agent 演练、新会话实际行为和真实安装验收分别报告。
