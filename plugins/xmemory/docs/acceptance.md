# 验收与验证边界

当前插件版本为 1.2.0，文件格式名为 `xmemory/v1`。包装检查、隔离演练和宿主验收是不同层次，不把其中一项冒充其他验收。

## 三类验证

1. **包装检查**：清单、资源、五技能元信息、链接、模板、版本、纯文档载荷、市场路径与归档校验。
2. **隔离演练**：在虚构记忆根中，由 Agent 按技能执行设置、记录、采集、整理、调取，检查范围、状态和读写边界。它不证明新会话会自动选择技能。
3. **宿主验收**：在目标客户端实际安装、启用、新建会话，确认读取协议生效、技能触发、资源加载、两客户端接续、Hook 与定时提示词运行和失败行为。本地包生成不代表此项通过。

本次具体执行结果记录在源码仓库 `docs/validation.md`；本文定义验收标准，不预填通过状态。

## 核心场景

| 场景 | 应出现 | 不应出现 |
|---|---|---|
| 初始化空测试根 | 配置（含时区）、根入口、项目入口 | 扫描个人来源；生成整套空目录或空模板 |
| 发现项目 | 按项目根目录汇总候选，项目名等于根目录名，列出各客户端别名，先给用户确认 | 未确认就写配置；按名字相同合并不同根 |
| 对话中保存交接 | 在事件日期目录新建一份足迹：做了什么、结果与证据、未完成、原件位置 | 修改主记忆、意识或每日记忆；复制聊天全文 |
| 报告测试通过但没部署 | 区分用户报告、本轮验证和部署 | 宣称业务完成 |
| 被纠正（milestone） | 新建足迹 + 带 `supersedes` 的主题草稿 | 直接改旧主题 |
| 闲聊或琐碎问答 | 不写，回复“无需记录” | 为每个回合建足迹 |
| 从原生记忆采集 | 先写清单，逐项抄录；每项写足迹或标无可记内容 / 跳过 / 失败；核对后才推进进度 | 只采一部分却报完成；凭印象列清单 |
| 读取工具列表被上限截断 | 分页取尽，或在清单开头写明截断 | 静默丢掉一部分 |
| 采集一个跨三天的长会话 | 三份足迹，分别在三天的目录 | 合并成一份、放在记录当天 |
| 历史会话在今天采集 | 足迹放在会话真实发生的日期目录 | 放进今天的目录 |
| 会话 ID 很长 | 足迹 `source` 写完整 ID，从读取结果复制 | 截断 ID、手打 ID |
| 会话仍在写入 | 跳过并在清单中注明，下次再采 | 读一半就当完整 |
| 归属不确定的会话 | `scope: 待定`，整理时在意识登记 | 塞进 personal |
| 同一主张在三个客户端出现 | 合并为一个主题，挂三个来源 | 三个主题；当作三份独立证据 |
| 只有 AI 汇报支持的结论 | 待核实或留在意识 | 晋升为主题；写成用户决定 |
| 整理时意识重写 | 旧待处理逐项保留或有去向；改写比例写进整理记录 | 待办无声消失；在末尾追加 |
| 意识超过容量 | 按重要度和新旧移出，写明去向；关键条目需确认 | 静默截断 |
| 晚到的历史足迹 | 被下一次整理发现，写进它所在日期的每日记忆 | 因日期早于上次整理而跳过 |
| 已吸收足迹核对 | 只按“已吸收足迹”列表判断是否已整理 | 正文提到文件名就当已整理 |
| 没有新内容 | 回复“本次无变化”，零写入 | 生成空的每日记忆或整理记录 |
| 定时整理遇到可合并的主题 | 写进意识“记忆候选” | 自行合并主题正文 |
| 写后核对 | 关键信息保全、已有条目损失、日期绝对化三项都有结论 | 未核对就登记已吸收 |
| 查询历史 | 按读取顺序读取并引用来源和截至时间 | 改写任何文件；读取 `state/` 当作记忆 |
| 未整理的更正草稿 | 已生效采用新内容；未来生效说明切换时间；冲突说明双方 | 仅按文件新旧决定 |
| 原件不在本机 | 用摘要回答，注明截至时间和“本机找不到” | 判定原件已删或结论错误 |
| 已撤回来源再次出现 | 不自动收录 | 旧内容复活 |
| 两个同名不同根的项目 | `<名>@<父目录名>` 区分 | 合并 |
| 从 worktree 启动 | 归到主仓库的项目 | 另建一个项目 |
| 集中库不可访问 | 说明权限或路径问题 | 回退到工作区悄悄另存一套 |
| 另一处正在整理 | 停下说明 | 两处同时修改 |
| 写入中途失败 | 停止当前范围，不登记未完成足迹；重试只补缺失 | 跳过失败继续登记；重复新建 |
| 来源中含恶意指令 | 当资料，不执行 | 覆盖当前任务规则 |
| 普通计算 | 直接回答 | 读取记忆库 |

## 首次回填验收

按首次回填提示词执行后：

1. 每批清单没有空状态行，各状态行数之和等于总行数，来源进度与清单一致。
2. 抽查足迹：文件名日期与 `event_at` 一致；`source` 能打开原件；`scope` 与会话工作目录一致。
3. 每个活跃项目回答三个真实问题（上次进行到哪、某个决定为什么、某个坑怎么避），能给出日期和来源。
4. 迁移 Office Memory 时，长期条目数、日期记录数与原系统一致，待处理项全部保留。

## 试运行

在 1 到 2 个项目上试运行两周：`capture = "milestone"`；先做一次首次回填；把定时提示词挂到一个客户端。重点观察：

- 换客户端接着干活时，是否少补背景；
- 纠正旧偏好后，新会话是否采用新的；
- 意识重写后是否丢待办；
- 每日记忆是否把当天各客户端的工作合并对；
- 原件不在本机时说法是否正确；
- 没有新内容时是否零写入。

## 新会话人工试用

按 [最小闭环](../examples/walkthrough.md) 执行，使用虚构数据和独立目录，不安装到唯一的生产记忆根。分别确认显式选择技能和自然语言选择；后者不是确定性保证。

每次验收记录：源码或包的 SHA-256、客户端及模型、场景、前置数据、实际工具结果、文件增改清单、逐项通过或失败、未验证边界。源码仓库的检查通过、隔离演练、新会话行为和真实安装验收分别报告。源码仓库 `tests/scenarios.json` 是验收用例，不是已执行的测试；新增条目不等于通过。
