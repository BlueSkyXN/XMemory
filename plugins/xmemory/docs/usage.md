# 使用指南

## 三种请求

| 请求 | 执行方式 |
|---|---|
| 整理某客户端、项目或时间范围的材料 | xmemory-update：采集有用变化，写笔记，整理主记忆，再按需调整入口 |
| 查过去的约定、经验或接续项目 | xmemory-recall：入口 → 相关主记忆 → 必要笔记或原件，保持只读 |
| 记住当前对话的一项要求或更正 | xmemory-note：短笔记并当轮更新适用的有效结论 |

“只采集先不整理”“只整理已有笔记”分别限定 update 的阶段。只采集时主记忆保持原样；若新材料影响已有当前结论，在入口留下短提示，供后续任务理解变化。普通补充或未采纳方案只留笔记。用户明确限定只能写笔记时遵从文件范围，并说明尚未进入常规读取入口。纯现状问题只读，遗忘和结构修复按明确请求执行。

## 形成与更新

一份来源可以无产出，也可以与其他同源材料合并为一篇笔记。笔记按工作主题成文，日期优先事件发生日；补录不冒充今天发生。同一工作继续更新原笔记，独立更正可另记并关联。

主记忆保留当前采用的结论、适用范围、条件、重要结果和未完成事项。详细经过留在笔记；入口只维护少量高频要点与阅读路线。没有变化不重写。

## 更正与中断

更正前先在入口的“待处理”部分记下范围与明确新要求，再保存笔记、更新主记忆。相关主记忆和入口同步并回读确认后，才移除本项提示；只采集或只记录时保留提示，其他待办保持。若中断，下次只处理相关提示。

普通查阅先处理入口中相关的更正、遗忘和待核查提示，再判断内容是否足够。范围清楚的更正可直接使用，笔记尚未创建也适用；待核查保留未知。信息不足或用户需要溯源时再展开历史。稳定约定可以直接使用，外部状态按实际任务检查。具体规则见 [维护约定](../skills/xmemory/references/maintenance.md)。

## 遗忘

明确指定要遗忘的结论、主题或来源。update 先留下最小排除约束，再清理本库相关笔记与有效知识；其他独立来源支持的内容保留。后续采集读取入口的约束，避免旧来源重新带入。排除说明不复制被遗忘正文，原生来源与外部副本分别处理。

## 检查和剩余

日常回读本次修改即可，不要求每轮做独立模型评测。需要机械盘点时可用 [status](../skills/xmemory/references/status.md)，报告不代表语义正确或历史覆盖完整。

本轮未读材料和待办在维护对话中具体说明。文件更新时间不能证明全部来源已处理；本版允许有界复读，避免为严格去重建立额外平台。
