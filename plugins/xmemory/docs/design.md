# 设计说明

宿主提供模型、文本文件工具与执行时机。XMemory 用三个 Skill 完成选材、提炼、整合、读取和明确反馈；可选读取器解决来源格式，status 只盘点本库文件。

| 内容 | 职责 | 更新方式 |
|---|---|---|
| notes | 有用工作、变化、条件与必要来源 | 同一工作增量更新，独立更正可另记 |
| MEMORY.md | 跨材料整合后的有效知识 | 局部替换变化的结论，保留其他范围 |
| memory_summary.md | 少量高频要点、导航和影响当前使用的短提示 | 要点、路线或相关提示变化时更新 |

更正和影响已有当前结论的变化通过入口短提示衔接分步写入；只采集时保留提示，主记忆不整合。读取先处理相关提示，再判断是否足够；明确更正可直接采用，待核查保留未知。普通查询无需扫描全库。指定遗忘用入口内的最小排除约束防止重新采集。规则见 [内容约定](../skills/xmemory/references/format.md) 和 [维护步骤](../skills/xmemory/references/maintenance.md)。

无价值允许无产出，原生会话与摘要同源时合并，用户纠正只在其适用范围内生效。提炼保留建议、决定、实际结果与未知之间的区别。

整合沿用 Codex 的内容取舍：单次安排保留在所属任务，主记忆维护能帮助相似后续任务的具体知识；后来的明确更正替换或收窄旧表述，其他有效内容保持稳定。历史执行细节留在笔记，本轮处理回执在对话汇报，入口保留要点与导航。方法的条件和关键细节继续保留，不以压缩字数代替整合。

采集时分清用户表达、助手行为与摘要作者的推断。原生摘要可复用，但其栏目名不能把作者推广变成用户的长期要求。新摘要省略旧知识也不表示撤回；需要判断旧条目的范围时，定向读取相关已知来源，保留仍有效的内容。

正式根固定为用户 home 下的 `.agents/memory/`，共享记忆独立于客户端。内容全部为 Markdown，不要求配置、状态数据库或中间交换文件。外部调度不属于 XMemory；没有文件访问能力的宿主不能直接访问本机记忆。

同一根按单写者方式维护，暂不提供并发协调和跨机器同步。原生基线的效果比较、不同宿主自然触发和长时间维护成本需分别验证。
