# XMemory 1.5.2 设计

## 职责

| 角色 | 工作 |
|---|---|
| AI 按技能 | 建库、选择来源、制作记录、更新六类对象、整理、遗忘、生成告知 |
| 只读 status | 库内更新线索、断链、字段、时间、疑似秘密、入口大小、来源记录时间 |
| Conversation Readers（可选） | 客户端会话 list/read/search；独立安装 |
| 客户端 | 当前代理和定时调度 |

对象与操作见 [技能](../skills/xmemory/SKILL.md)。目录树就是记忆，不使用 git、队列、锁、ledger、持久化游标或运行日志。排除列表属于配置，其他事实与来源写在 Markdown 中。

## 程序范围

唯一 CLI 为 `xmemory.py [--root DIR] status`，`--root` 也可放在 status 后。缺省根按 `XMEMORY_ROOT`、`~/.agents/memory/` 选择。支持 Python 3.9+，配置解析器沿用既有 TOML 子集（表、字符串、整数、布尔与数组），无第三方依赖。

读取配置与库内 Markdown，不跟随内部 symlink，不检查库外链接和客户端数据。报告 JSON 只输出问题类型、文件和位置，疑似秘密不回显原值。缺库或无效配置退出 2；正常报告退出 0，即使报告中有待修问题。不会自动修复或创建任何文件。

## 1.5.1 的改进与边界

- 正文修改总是使用真实 `updated`，让下游看到变化；未完成的派生对象暂不覆盖，partial 记录显式保留读取缺口。时间与字段仍依赖代理如实填写，status 不校验正文语义。
- 日常增量只处理新材料及涉及的主题。客户端每 7 天另行触发完整整理；库中不保存上次整理时间，status 不再根据索引年龄产生整理到期提示。未设置客户端任务就没有自动周期整理。
- 跨日文件仍是一份记录，可用 `event_days` 关联多个有依据的日总结；省略该字段兼容 1.5.0 的单日记录。程序不会补造间隔日期，旧材料要经 AI 回查才补其他事件日。
- 新会话身份使用 `client:<原生 ID>`，读取器引用另行保留。旧身份继续精确匹配并提示复核，程序不自动迁移，也不把读取器可能回退的文件名认作原生 ID。
- 来源参考补充 WorkBuddy 工作区记忆与 Qoder CN CLI 项目记忆；它们是有版本边界的查找线索，使用时仍核实当前配置。
- 二手材料缺少会话身份时，只能按可追溯证据清理。备份由遗忘技能另行处理；程序不负责原客户端或外部副本清除。
- 不支持多机同步、并发写协调、自动注入、使用统计或技能自动晋升。仓库提供合成事实与标准答案供独立新会话验证；程序测试和样例审查不代表真实客户端中的记忆质量与主动调取已验收。

## 1.5.2：更正的写入与查阅（待发布）

- 明确新增或更正长期偏好、项目决定时，笔记技能同步相关画像或主题条目；用户只要记录时除外。局部同步保留其他内容，不声称其他记录已吸收。
- 查阅补查相关记录中的更正、撤回和替代，不只沿旧入口链接，也不把文件更新时间当吸收水位；可以直接据新记录回答，仍保持只读。
- 全局摘要发现已有画像/项目入口有明确待处理新来源时提示 review，并在报告的 `upstream_updates` 中列出路径。记录的固定外部未检查提示不向上传播。
- 文件格式仍为 `xmemory/v1.5`，没有新增运行状态、后台或命令。正式发布时间与版本以 Release 为准。

## 旧库

格式为 `xmemory/v1.5`。1.4 运行时整体退役，旧库不会自动迁移、覆盖或接管。用户确定新目录或归档旧库后，按设置技能重建；1.4 源码和发布包仍由既有版本标签保留。

1.5.0 库可以直接由 1.5.1 读取。跨日字段为可选补充；身份复核由技能根据原件执行，不在安装或 status 时改写库。1.5.1 写出的 `event_days` 在 1.5.0 中不会参与跨日检查，因此跨日行为应使用新版本验证。
