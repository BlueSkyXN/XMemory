# 研究 demo 与已有资料

## 正式版本从这里开始

XMemory 1.0.0 是首个正式插件版本，`config.toml` 使用首个正式文件格式 `xmemory/v1`。研究 demo 仅用于验证想法，不属于正式发布历史；它内部曾使用的版本号或格式字符串不决定正式版本编号，也不构成兼容承诺。

1.1.0 在 `xmemory/v1` 名下重新定义了文件布局：两层结构、带 YAML 头部的记忆和事件文件、当日文件。1.0.x 没有投入使用的记忆库，因此不提供升级步骤。如果确有按 1.0.x 约定建立的库，旧文件按原样可读，整理时再逐步转换，不批量重写。

安装正式插件不需要安装 demo、不需要经过升级步骤，也不沿用 demo 的文件操作 helper。默认在用户主目录下的 `~/.agents/memory/` 建立集中库，不在项目中各建一套。初始化仍需明确请求并检查已有内容，不能覆盖未知数据。

## 已有内容默认不接管

安装不会读取或改变研究 demo、Office Memory 或客户端原生记忆。发现目标目录已有未知内容时，先确认归属；即使文件名或格式字符串相同，也要核对配置字段、目录和维护主体，不能自动视为正式 XMemory 记忆库。

项目里的 `.agents/memory/` 与用户级的 `~/.agents/memory/` 只是名字相同：前者可能是 Office Memory 等其他流程的结果目录，不是 XMemory 记忆库。

Office Memory 的后续方向是迁入用户级集中库并停用旧流程，不是永久并行维护两套正式记忆。迁移尚未实施时，登记为 `owner = "external"` 并只读其入口，不因安装 XMemory 自动搬文件或接管正文。

## Office Memory 迁移步骤

迁移在 XMemory 试运行之后、由用户另行明确请求时进行：

1. 核对来源与目标、保留范围和引用；迁移期间 Office Memory 继续按原流程维护。
2. 长期条目逐条转成主题记忆，保留复查日期。做法类条目归入经验并写出适用条件；已有正式 Skill 的只留入口和例外。
3. 当前认知转成按工作线分节的近况；待确认事项逐条确认去向，久无依据的移入积压。
4. 历史日期记录留在原处，登记为只读来源，不转换成事件文件。
5. 切换读取入口，验证当前事项和长期结论都能找到，再停用旧写入流程。

没有完成这些步骤，就不能只改 owner 宣称迁移成功，也不自动删除历史资料。

## 明确需要复用研究资料时

将它当作一次有范围的资料接入，而不是版本升级：

1. 用户选定需要复用的资料，确认读取范围和目标项目。
2. 设置技能登记只读来源或外部入口，不自动采集。
3. 用户明确要求采集时，由采集技能读取必要内容，保存摘要、条件和来源。
4. 用户要求整理时，再判断哪些内容进入近况或长期记忆；不复制整套研究目录，不假定研究结论已经验证。
5. 保留原件，不改写来源。接入完成不授权删除研究材料或切换客户端规则。

研究 demo 自身的说明、模板和虚构测试不是用户事实，不写入正式记忆。确有个人资料需要复用时，只处理明确选定内容，不按 demo 的目录结构机械转换。

## 多客户端与多设备

共享一套数据需要各客户端都能访问同一个根。多台机器时同步整个库，同步方式（同步盘、GitHub 私有仓库等）由用户选择；跨设备复制、云盘冲突和权限由用户现有系统处理，不属于插件功能。记忆内容不带设备特征，各台机器只采集自己能读到的来源；除配置外只有整理修改已有文件，同一时间只在一处整理。
