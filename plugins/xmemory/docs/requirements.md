# 原始需求的覆盖情况

本文按 1.1.0 设计更新，设计全文见 [设计](design.md)。

## 先区分技能、触发和存储

XMemory 负责"做什么、读哪里、留下什么、怎样找到"。模型使用宿主现有的文件工具执行；插件不提供独立可执行工具。

"何时运行"由两样东西决定：对话中，读取协议提示 Agent 在合适的时候读取或记录；定时运行，由用户把定时提示词挂到某个客户端的定时任务上。插件本身不计数、不监听、不在后台运行，也不带 Hook 程序。文件存在不代表客户端会自动读取。

## 逐项对应

| 原始想法 | 当前对应 | 边界 |
|---|---|---|
| AI 在对话中写入（被动采集） | record；`capture = "milestone"` 时，被纠正、说明偏好、做出决定和阶段交接也会记录 | 依赖宿主按读取协议调用，不保证每次触发 |
| Hook 每 N 步或由 AI 自主判断写入 | 不提供 Hook 程序；如需宿主触发，建议按事件（阶段完成、压缩前、会话结束）调用 record | 按步数触发噪声大、成本高 |
| 定时 Agent 主动采集 | collect 加 curate，由用户把定时提示词挂到任一客户端 | 插件不带调度器 |
| 多端会话、审阅记录、日志 | collect 按登记来源读取；优先读各客户端已有的记忆摘要和已有的日报类产物，原始会话只补缺口 | 依赖宿主真实可用的读取方式，不解析未知数据库 |
| 工作区文件变动 | collect 先用文件列表、修改时间、Git 查询缩小候选，再读必要正文 | 时间戳只是线索，不证明业务完成 |
| 总结与索引，不复制原文 | 事件文件保存摘要和地址，原件留在原处 | 不保存整段聊天或完整日志 |
| 意识区（大幅重写、近期优先） | 近况由整理整篇重写；旧待办的去向写进当日文件；久无依据的移入积压 | 不规定重写比例；近期信息只用来刷新状态，不自动推翻更早的明确决定 |
| 主记忆：抽取关键信息并引导子文件 | 入口放常驻一行条目和带一句结论的索引，详情在主题记忆 | 入口保持短 |
| 足迹与索引 | 事件文件只新建；相关结果保存并回读确认后，当日文件最后登记已处理事件 | 未处理事件不按年龄排除；已处理不等于业务完成 |
| 每日记忆 | 当日文件 `YYYY-MM-DD.md`，按整理日期，每次整理追加一节 | 只由整理写 |
| 整理中断后接续 | 停止当前范围后续写入；按事件地址、记忆 ID 和行动 key 核对，重试只补缺失步骤 | 保留已保存内容，不承诺事务或并发安全 |
| 项目或路径的持续跟踪（总结加详细） | 近况是总结，可重写；事件文件是详细，只增不改 | 总结和详细分开存放，不挤进一个无限变长的文件 |
| 让 AI 自己搜 | recall 按读取协议逐层读：入口、近况、未收录事件、主题记忆、原件 | 不需要检索服务 |
| 跨设备、服务器、GitHub | 记忆内容不带设备特征；地址分库内、项目、云端、本机四类；同步方式由用户选 | 插件不提供同步 |
| 本地与云端互相同步的文档 | `artifacts` 列出各载体，`primary` 标出主本，`synced` 记录最近一次确认一致 | 两份是否一致是会变的事实，用前核实 |

## 用户级集中存储，不是项目各存一套

默认数据根是 `~/.agents/memory/`，其中 `~` 指用户主目录，与当前工作区无关。同一台机器上的客户端共用该用户的记忆根；多台机器使用同一逻辑记忆库，各机器默认位置为 `~/.agents/memory/`，通过用户选择的同步方式保持内容一致。根近况维护跨项目重点，项目内容放在库内 `projects/<id>/`。

项目身份不靠目录名。依次看用户是否指明、项目根 AGENTS.md 里声明的项目 ID、Git 远程地址，最后才看配置中的候选路径。不在项目根自动创建 `.agents/memory/`、其他数据目录或软链接；已有项目目录中的旧记忆是来源，不是自动覆盖默认根的候选。

这是用户级全局存储，但内容仍分适用范围：个人要求可跨项目使用，项目决定只在对应项目适用。集中不等于每次扫描或注入全部项目。明确指定其他根时，也应让相关客户端一致使用该根，不能按工作区悄悄分叉。多台机器共用时同步整个库，同步方式由用户选择。

Office Memory 后续可以迁入集中库并停用；迁移执行前，既有数据仍由原流程维护，XMemory 只读其登记入口。目录名字相同不表示可以直接接管格式。安装目录、技能发现目录、市场目录和集中记忆目录是四件事。

## 完成程度

1.1.0 已实现文件约定与五技能方法：两层结构、五技能的写入分工、读取协议、定时提示词、四类地址和多设备约定。它覆盖“按需与定时的采集、整理、调取”的轻量核心，不等于无人值守全自动记忆。自动触发、定时运行，以及多客户端、多设备的实际效果，需要宿主支持并完成相应验收，不能用文档声称已经具备。
