# XMemory 1.5 技能稿

日期：2026-10-12。阶段：技能、格式与报告约定草稿，供审阅。

本目录是 1.5 的开发稿，尚未进入插件或分发包。正式插件仍是 1.4.1；不要用其运行时操作 `xmemory/v1.5` 库。这里没有新增程序，也没有在真实记忆库执行采集或改写。

## 产品基线

- 记忆是一棵 Markdown 目录树。流程与判断由技能教 AI，不依赖 git，不维护队列、锁、ledger、游标或完成账本。
- 每个对象保存自己的 `updated`。只有遗忘排除列表需要跨轮保留控制信息，放在 `config.toml`。
- 六类对象分别工作：记录、全局日总结、项目总结、项目意识、用户画像、全局摘要。项目总结使用 `MEMORY.md` 索引加 `topics/` 多条内容；没有必须依次完成的流水线。
- Conversation Readers 另装、可选，来源由用户选择；缺少读取器时按来源参考只读探索。
- 唯一程序是只读 `status`。调度交给客户端，技能可以由任何代理执行。
- 遗忘跨所有对象传播；不纳入技能沉淀、使用统计、自动注入或多机同步。

## 本稿补充的执行口径

这些是让技能可执行的草稿约定，尚不表示程序已实现：

- `updated` 表示完成了该对象本轮范围内的检查和更新；不能用“编辑过文件的时间”掩盖未读来源。可以只做部分对象；一个对象的来源未处理完时，保留其原 `updated`。
- `status` 只读记忆根，不连接客户端。对外部材料是否变化，它报告未检查；各来源的最新记录时间是检索线索，不是完整处理游标。
- 项目总结的一次完整更新包含归入和整理；索引 `updated` 同时作为这次完整工序的完成时间。即使没有新记录，超过 7 天也复查；只改了局部主题而未完成整理时，不推进索引时间。因此不需要另加“上次整理”状态。
- `USER.md` 的变化也会使全局摘要需要更新。普通记录是否含跨任务偏好由 AI 判断，`status` 只提示待复查来源。
- 全局摘要按 UTF-8 的 10,000 字节计。意识的大小上限在产品定义中尚未定值：本稿只把 `awareness_max_bytes` 作为可选配置；未设置时报告实际大小和“未配置上限”，不暗用旧方案的 16 KB。
- 日总结中的非会话材料使用记录块；既有会话标识时仍按会话合并，避免同一会话的原始记录与导入摘要写成两次工作。

## 后续实施范围

技能稿审阅后，把这里的技能及资源应用到 `plugins/xmemory/skills/`，再按报告约定实现 `status`。届时统一退役 1.4 的写入运行时、内嵌读取器、任务与整合状态测试，并同步插件清单、市场描述、安装文档和打包检查。Conversation Readers 保持独立。

本阶段只核对技能 frontmatter、资源链接、配置和模板结构，以及典型请求的工序覆盖；这些检查不等于真实客户端行为验收。

## 本阶段核对结果

- 八个技能通过 `skill-creator` 的 frontmatter 与命名检查；技能之间及参考文件的本地链接和章节锚点可解析。
- 配置可用 TOML 解析，外部来源默认关闭；七种文件模板可解析 frontmatter，分别覆盖记录、日总结、索引、主题、意识、画像与入口。
- 来源参考表与产品评估中保留的表一致，没有复制本机身份、对话正文或私有项目路径。
- 主线程按“只更新意识”“只更新画像”“部分来源未读全”“只改日总结中的一个项目”“跨对象遗忘”走读工序：无需固定流水线，未完整处理的对象不会仅因写文件推进完成时间，遗忘沿来源清理。
- 尚未执行独立代理行为演练、真实客户端安装或 `status` 程序验收。正式插件及读取器的代码在本阶段保持 1.4.1 / 0.1.4。
